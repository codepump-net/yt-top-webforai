# Clinic content

`pages.json` contains 94 routes (93 patient/information/utility routes and a 404) with hospital information, questions, source links and related pages. `clinic.json` and `physicians.json` hold clinic identity and source-derived profiles. `assets.json` records hashes and provenance for the five optimized image files.

`case-links.json` links to 25 case articles on the original hospital site. Notices link to the original announcement board. This site runs alongside `yttop.co.kr`; it does not replace it. `page-intents.json` records the patient need for each public route and is consumed only by the internal build checks. Do not publish these internal records as hospital pages. See [the patient-content policy](../docs/patient-content-policy.ko.md) and [the page-by-page cleanup](../docs/content-audit-2026-09-11/README.md).

On 2026-09-11 the user explicitly confirmed that medical and operational review and publication checks were complete and instructed production deployment. `publication-approval.json` records that confirmation and binds it to the exact content, clinic facts, profiles, assets, case links, patient intents and renderer. This internal confirmation is not a named physician's review attribution; `reviews.json` remains empty because the user did not identify the individual reviewers. No clinician byline is invented. See [the release record](../docs/production-release-2026-09-11/README.ko.md).

`npm run build` creates a noindex review site. GitHub Pages currently uses repository variable `PUBLICATION_MODE=review` for the user's 2026-09-25 request to deploy before the director's review; pull requests also use review mode. All deployed pages are temporarily noindex. `npm run build:release` requires valid, unexpired evidence for the current content. Existing named clinical review records are still supported when the publication confirmation is absent. Changed content, scope, shared facts or rendering invalidate the recorded confirmation; do not automatically regenerate its digest during builds. The one-year expiry is an internal maximum validity policy, not a claim about the date of the medical review. Test fixtures exist only in unit-test memory.

The 53 questions in `measurement-queries.json` are an editorial evaluation set, not a measured list of frequent questions. The original 20 were extended by 12 research-derived items and 21 director-manuscript items; Q03 maps to the existing palpitations item. `measurement-conversations.json` adds 13 fixed, same-thread scenarios with 39 turns and manual accuracy criteria. No user Q&A text, patient image, medical record, API key or private reviewer document belongs in this public repository.

Blocks and questions support stable `id`, local `sourceIds`, and contextual `links` (`pageId`, optional `anchor`, `label`). Blocks can contain an accessible `table` (`caption`, `columns`, `rows`). Source IDs must exist on the same page; links and anchors must resolve. Source kinds distinguish hospital facts from medical references. An attached reference is not clinical approval. See [the improvement result](../docs/aeo-geo-improvement-results-2026-09-11/README.md).

`clinic.json` stores `addressParts` and time intervals. `web/src/lib/content-model.mjs` derives the display address, hours and JSON-LD from the same data. Manuscripts can reference `{{clinic.name}}`, `{{clinic.phone}}`, `{{clinic.address}}`, `{{clinic.subway}}`, and `{{clinic.hours.ID}}`. Both server rendering and build validation resolve these references before output. Do not copy contact values into prose. The director confirmed Saturday has no lunch break; Saturday hours are now included in structured intervals. `addressLabels` centralizes English and Chinese address renderings for all five translations and is available through `{{clinic.addressLabels.en}}` and `{{clinic.addressLabels.zh-Hans}}`. No coordinates have been invented.

Medical review records require `reviewerId` matching the actual reviewer's profile and name. No new review records were added. Approval digests use the resolved data returned by `loadContent()`, including the shared resolver in the renderer digest; do not hash only the raw clinic JSON.

See [the Korean handoff guide](../docs/development-handoff.ko.md) for editing, publishing, the review record schema and deployment.

Named medical approval is never inferred from a supplied manuscript heading.
