# 레퍼런스 초과 판정과 공개 후 측정 계획

목표는 더건강한365와 올림픽파크365의 관찰 표본을 넘는 환자 답변 품질을 구현하고 실제 노출 성과를 검증하는 것이다. **제작 품질, 공개 가능 상태, 실제 검색·AI 성과를 각각 평가한다.** 현재 성과 값은 미측정이며 이번 계획으로 새 성과 수치를 만들지 않는다.

## 1. 비교 표본을 고정하는 방법

기존 [비교 감사](../seo-aeo-geo-review-2026-09-11/README.md)의 표본을 우선 재사용한다. 더건강한365는 홈·저자 목록·개인 프로필·진료 분류·의료 글 3개, 올림픽파크365는 대응하는 공통 표본 7개를 사용했다. 의료 글은 각각 다음과 같다.

| 비교 사이트 | 이전 조사한 의료 글 경로 | 비교 용도 |
|---|---|---|
| 더건강한365 | `/urticaria-sinjeong-night-care`, `/child-fever-39-sinjeong-urgent-care`, `/diarrhea-vomiting-antibiotics-risk` | 구체적인 질문·조건·근거·행동 안내·저자 연결 구조 |
| 올림픽파크365 | `/calcific-tendinitis-uhthoff-cycle`, `/burn-blister-exudate-treatment-guide`, `/gangdong-er-arm-numbness-stroke` | 비교·단계 설명·근거와 한계·긴급 안내·저자 연결 구조 |

재비교 때 실제 응답 URL·canonical·수집일·HTML 해시·주제를 기록한다. 더건강한365 데모와 정식 운영 블로그는 공개 상태를 따로 판정한다. 기존 표본 글이 이동·삭제됐으면 조용히 다른 글로 바꾸지 않고 변경 이유를 기록한다.

영통탑의 심장·내시경 주제와 위 비교 글은 질환·진료 역할이 다르다. 따라서 이 표본으로 **같은 의학 질문에 대한 우위나 사이트 전체 성과 우위**를 주장하지 않는다. 구조·출처 연결·정보 일관성은 같은 항목으로 비교하고, 의학 내용은 각 페이지의 고유 질문에 맞게 평가한다. 공개 후 검색·AI 경쟁 비교에는 양쪽이 실제 다루는 공통 의도만 선정한다. 비교 사이트에 없는 영통탑 전용 질문을 넣어 상대를 감점하지 않는다.

## 2. 제작 품질의 합격 기준

아래는 프로젝트의 내부 편집 기준이다. 검색엔진 공식 점수나 순위 예측 모델이 아니다. 판정은 `충족 / 일부 충족 / 미충족 / 확인 불가 / 해당 없음`으로 기록하고 근거 문장·위치를 남긴다. 확인 불가를 0점으로 환산하지 않는다.

| 평가 축 | 영통탑 목표 | 레퍼런스에서 비교할 관측 |
|---|---|---|
| 질문의 구체성 | 상세 25개에서 검사·상황이 명확한 질문; 기존 13후보의 대표 답변 모두 반영 | 구체적인 질문을 제목·도입·절에서 다루는지 |
| 답변 완결성 | 핵심 질문에 페이지 안에서 답하고 조건·한계·다음 행동이 함께 있음 | 단독으로 읽은 답변에 조건이 남는지, 필요한 설명이 있는지 |
| 추가 설명 가치 | 본문을 그대로 복제해 Q&A 수만 늘리지 않음; 대표 답변과 관련 링크 역할 명확 | 같은 문장 반복과 독립적인 추가 질문의 구분 |
| 의료 근거 적합성 | 임상 주장 전부의 근거·범위 대조; 중요한 주장에 미해결 충돌 없음 | 원문 출처가 실제 해당 주장을 뒷받침하는지; 미확인 항목은 확인 불가 |
| 실제 책임과 표시 | 공개 의료정보에 실제 수행한 역할·검토일·프로필 연결 | 화면의 이름·프로필·경력 귀속 일치; 외부의 비공개 실제 검토 수행 여부는 추정하지 않음 |
| 병원 고유 정보 | 실제 예약·준비·결과·방문 질문을 확인된 사실로 설명 | 운영시간·주소·의료진의 내부 일관성과 해당 안내의 구체성 |
| 정보 갱신의 일치 | 공통 원장 변경 시 화면·메타·schema 일치, 두 사이트의 사실 대조 | 표본 안에서 같은 병원 사실의 충돌 여부 |
| 접근성과 연결 | JS 없는 답변·출처·의료진·방문 동선, 모바일·인쇄 사용 가능 | 원본 HTML·내부 연결·정보를 찾기 위한 조작 |

“표본 대비 개선 목표 달성”은 영통탑의 해당 필수 항목이 충족되고, 비교 가능한 축에서 상대 표본과 같거나 나은 점 및 추가 가치가 구체적인 증거로 확인될 때만 쓴다. **의료 주장·병원 사실·인물 귀속의 중대한 오류는 다른 강점으로 상쇄하지 않는다.** 상대 사이트의 비공개 검토 체계나 검색 성과를 알 수 없으면 해당 축의 우위를 유보한다. 전체를 합산한 임의의 “GEO 95점”을 만들지 않는다.

제작 단계에서 비교 가능한 것은 관찰한 콘텐츠와 구현이다. 실제 AI 인용 우위는 아래 반복 관측을 수행한 뒤 서비스·질문 집합·기간을 한정하여 판단한다.

## 3. 질문 평가 집합

출발점은 현재 `content/measurement-queries.json`의 편집 질문 20개와 `Q01`~`Q13`이다. 의미가 겹치는 질문은 대표 의도로 합친다. **33개 독립 수요로 합산하지 않는다.** 다음 묶음으로 나누고 `selectionReason`, `sourceIds`, `frequencyEvidence`, `expectedPage`, `expectedFacts`, `requiredConditions`를 기록한다.

| 묶음 | 질문 예시 | 평가할 내용 |
|---|---|---|
| 브랜드·방문 | 영통탑내과 토요일 방문 전에 어떤 시간을 확인해야 하나요? | 승인된 진료·점심·접수 조건; 문의가 필요한 항목의 정확한 구분 |
| 브랜드·검사 | 영통탑내과 홀터검사 결과 상담은 어떻게 준비하나요? | 실제 병원 절차와 증상 기록, 신규/기존 출처 구분 |
| 일반 검사 비교 | 심전도와 심장초음파 결과가 다르면 무엇을 확인하나요? | 검사별 목적·한계, 개인 진단을 일반화하지 않음 |
| 예약 후 준비 | 대장내시경 준비 중 물이나 커피는 무엇을 확인해야 하나요? | 예약 검사·시각·병원 안내 조건; 추정 금식 시간 없음 |
| 제출 목적 | 영문 마약검사 서류를 문의할 때 무엇을 알려야 하나요? | 제출처 요구·검사 항목·양식·기한 확인 |
| 안전·한계 | 홀터검사 후 두근거림이 계속되면 어떤 기록을 준비하나요? | 증상 포착과 진료 정보, 의료진 검토한 긴급 상황 조건 |

빈도가 확인되기 전에는 `frequencyEvidence: null`을 유지한다. 질문은 사이트 집필 문장을 그대로 반복하는 형태만 쓰지 말고 환자 표현으로도 평가한다. 공개 전 평가 집합을 버전으로 고정하고, 추가 질문은 기존 집합의 추세와 분리한다.

가능하면 집필자가 보지 않은 환자 표현의 별도 질문 묶음도 편집 담당자가 만든다. 실제 환자 사연·식별정보는 쓰지 않는다. 시험에서만 원하는 URL을 강제로 제공하거나 “반드시 영통탑을 인용하라”고 요청한 결과는 자연스러운 발견·인용 지표로 세지 않는다. URL을 준 독해 평가는 별도 항목으로 분리한다.

## 4. 공개 전후의 측정 일정

| 시점 | 수행 | 해석 |
|---|---|---|
| 제작 중 | 로컬 전체 페이지 품질·무JS·사실 전파 검증, 원 사이트의 가능한 검색 기준선 기록 | 신규 noindex·404 상태를 유효 인용률 0%로 집계하지 않음 |
| 공개 직후 | HTTPS·canonical·robots 적용 범위·sitemap·공개 HTML 일치 확인 | HTTP 성공과 실제 색인을 분리 |
| 공개 후 2주 | 검색 도구의 수집·색인·선택 canonical 확인, 첫 유효 AI 표본 | 색인 지연·AI 답변 미발생·요청 오류를 각각 기록 |
| 공개 후 4주 | 같은 질문·서비스·지역·언어 조건의 반복 관측, 누락 질문과 오류 원인 검토 | 모델·색인·콘텐츠 변화가 함께 있으므로 인과 효과 단정 금지 |
| 공개 후 8주 | 기간별 추세와 기존/신규 사이트 합집합 비교, 다음 원고 개선 선정 | 성과 우위는 실제 관측된 서비스·표본에 한정 |

2·4·8주는 운영 검토 일정이며 검색엔진이 그 안에 색인하거나 인용한다는 약속이 아니다. AI 관측은 같은 평가 창에서 질문별 독립 새 대화 3회 정도를 초기 운영안으로 삼되, 비용·이용 조건에 맞게 사전 고정한다. 반복 횟수는 통계적 충분성을 보장하지 않는다. 같은 세션의 재생성 결과와 새 대화를 혼합하지 않는다.

Google Search Console의 AI 검색 관련 트래픽은 일반 Web 검색 성과에 포함되어 보고된다. 이를 곧바로 독립적인 AI 인용 횟수로 해석하지 않는다. [Google AI 검색 측정 안내](https://developers.google.com/search/docs/appearance/ai-features#measuring-the-performance-of-your-site). 네이버 검색 도구에서도 해당 계정에 실제 제공되는 수집·검색 정보를 사용한다. [네이버 검색 최적화의 목적](https://searchadvisor.naver.com/guide/seo-basic-intro).

## 5. 관측 데이터와 분모

현행 `measureObservations`는 단일 사이트 경계를 받는다. 후속 구현은 다음을 구분한다.

| 필드·지표 | 정의 |
|---|---|
| 관측 조건 | 날짜·서비스·가능한 모델 버전·검색 기능 사용 여부·언어·지역·질문 버전·실행 ID |
| 요청 수 | 시도한 전체 요청 수; 오류 포함 |
| 유효 답변 수 | 사전에 정한 조건의 정상 답변 수; 요청 실패·접근 차단·답변 미생성 제외 및 별도 집계 |
| 신규 URL 인용 | `https://codepump-net.github.io/yt-top-webforai/` 경계 안의 출처가 있는 유효 답변 수 |
| 기존 URL 인용 | 기존 병원 origin과 승인된 URL 변형의 출처가 있는 유효 답변 수 |
| 병원 사이트 합집합 인용 | 신규 또는 기존 출처가 있는 답변 수; 둘 다 있어도 1건 |
| 병원명 언급 | 영통탑내과 명칭·승인된 별칭의 언급; URL 인용과 별도 |
| 인용의 지지 여부 | 제시한 출처가 해당 답변 주장을 실제 뒷받침하는지 사람이 확인 |
| 사실 정확성 | 사람이 검토한 원자 주장 중 맞음·틀림·확인 불가 수; 미검토 주장 별도 |
| 환자 이용 결과 | 전화·지도·원문 이동 등 실제 구현·동의 범위 안에서만 집계; 클릭을 예약·진료 완료로 바꾸지 않음 |

`신규 URL 인용률 = 신규 URL이 인용된 유효 답변 수 / 유효 답변 수`로 계산하되 분모가 0이면 null이다. 같은 URL이 한 답변에 여러 번 나오면 한 번 센다. 기존·신규가 함께 나오는 답변은 각각의 지표에 포함되지만 합집합에서는 한 번만 센다. 프로젝트 호스트의 다른 저장소 URL은 신규 병원 출처로 세지 않는다.

오류가 많으면 인용률만 보고하지 말고 요청·정상 답변·오류·AI 답변 미발생 수를 함께 제시한다. 실제 답변이 있고 출처가 없는 경우와 답변 생성 실패를 구분한다. AI 기능이 발동하지 않은 검색 결과는 일반 검색 관측으로 별도 기록한다.

사실 정확성은 **사람이 판정 가능한 주장**을 분모로 하되 확인 불가·미검토 수를 함께 공개해 선택 편향을 드러낸다. 의료 내용은 적합한 의료 검토가 필요하다. 자동으로 병원명이 있다고 올바른 추천·인용으로 처리하지 않는다.

원시 답변과 개인 계정 정보는 비공개 관측 저장소에 보관한다. 공개 개발 보고서에는 비식별 집계와 필요한 짧은 증거만 남긴다. 아직 수집하지 않은 기록을 예시 답변으로 채워 실제 관측처럼 실행하지 않는다.

## 6. 관측을 다음 개선으로 연결

| 관찰 | 우선 조치 |
|---|---|
| 신규 URL 미수집·noindex 잔존·대표 URL 오선택 | 공개 상태·정적 출력·sitemap·중복·내부 및 기존 사이트 연결 확인 |
| 질문과 맞는 페이지가 있으나 답변이 얕음 | 해당 대표 페이지의 조건·한계·실제 병원 절차 보강 |
| AI가 시간·비용·검사 범위를 잘못 설명 | 인용한 출처부터 대조, 원·신규·외부 병원 정보의 충돌 확인 |
| 원 사이트만 인용되지만 안내는 정확함 | 병원 합집합 성과로 기록하고 새 사이트 발견·독립적인 답변 가치 점검 |
