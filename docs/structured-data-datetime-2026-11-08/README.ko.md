# dateModified 날짜·시간 형식 수정

2026-11-08 사용자가 `‘dateModified’의 datetime 값이 잘못됨` 문제의 해결을 요청했다. 이 문서는 내부 구현·검증 기록이며 공개 웹 출력에 포함하지 않는다.

## 원인과 수정

기존 JSON-LD는 `updatedAt`의 날짜 값(`2026-10-15` 등)을 `WebPage`와 `Article`의 `dateModified`에 그대로 사용했다. Schema.org는 Date와 DateTime을 허용하지만 Google의 Article 정의는 ISO 8601 DateTime을 기대한다. [Google 공식 정의](https://developers.google.com/search/docs/appearance/structured-data/article?hl=ko) · [Schema.org](https://schema.org/dateModified).

`pages.json`에 선택 필드 `modifiedAt`을 추가하고, 확인된 시간대 포함 시각만 `dateModified`로 출력한다. 예를 들어 대장내시경 준비 안내는 `2026-11-07T22:07:11+09:00`을 사용한다. 환자에게 보이는 내용 수정일과 사이트맵의 `lastmod`는 기존 `updatedAt`을 유지한다. 알려진 수정 시각이 없는 새 원고는 `modifiedAt`을 생략할 수 있으며, JSON-LD의 선택 속성도 생략한다. 임의의 자정·정오나 빌드 시각을 넣지 않는다. 최초 게시 시각을 추측해 `publishedAt`에 채우지 않는다.

135개 페이지별 마지막 원고 레코드 변경 커밋과 그 committer 시각을 대조했다. 모두 기존 내용 수정일과 한국 날짜가 일치했다. Git 기록 시각은 원고 변경 이력의 시각이며 실제 의료 검토나 배포 시각이라는 뜻은 아니다. [페이지별 커밋·시각 근거](modification-provenance.json).

## 검증 기준

- 원고 검사에서 날짜만 입력한 값, 시간대 누락, 존재하지 않는 날짜, 미래 시각, 한국 날짜와 `updatedAt`의 불일치를 거절한다.
- 구조화 데이터 회귀 검사에서 모든 페이지·기사의 수정 시각, 기존 게시 시각 보존과 미확인 시각의 생략을 확인한다.
- 정적 출력 검사에서 모든 JSON-LD의 `dateModified`와 `datePublished`가 시간대를 포함한 유효한 ISO 8601 DateTime인지 검사한다.
- 기존 공개 검증의 범위·내용·renderer digest·유효기간 확인을 유지한다. 이번 요청 범위는 날짜 메타데이터 수정이며, 기존 의료·운영 확인 시각·기간·대상과 환자용 본문·출처·진료 사실은 바꾸지 않는다.
