# 환자용 병원 홈페이지 목적에 따른 전수 정리

2026-09-11. 적용 대상: 변경 전 76개 계획 경로, 공통 화면, 검색 목록, 메타데이터, 구조화 데이터와 정적 배포 파일. 판단 기준은 [환자용 콘텐츠 기준](../patient-content-policy.ko.md)이다.

이 사이트의 목적을 **기존 영통탑내과 홈페이지와 함께 운영하는 환자용 병원 소개·진료·검사·방문 안내**로 명시했다. AEO·GEO는 이 정보를 찾고 이해하기 쉽게 만드는 기술적 목표다. 제작 과정이나 조사 결과를 환자용 내용으로 게시할 이유가 되지 않는다.

현재 경로는 **45개(환자용·이용 기능 44개와 404 1개)**다. 31개 상세/정책 경로를 공개 출력에서 제외했다. 독립된 사례 글이 부적절해서 사례 자체를 없앤 것이 아니라, 현재 구현의 반복적인 상세 요약을 원문을 찾는 목록으로 정리했다. 공지 원문과 기존 사이트의 운영을 수정하거나 삭제하지 않았다.

변경 전 모든 경로의 개별 판단·이유·연결 대상은 [76개 페이지 판단표](page-decisions.csv), 현재 각 경로가 해결하는 환자의 필요는 [페이지 목적 원장](../../content/page-intents.json)에 있다. [이전 원고 보관본](retired-pages.json)은 이번 판단을 추적하기 위한 내부 개발 기록이며 정적 사이트에 포함되지 않는다.

## 유지한 내용과 이유

병원 소개·의료진·진료 및 검사·검진·건강정보·방문 안내는 환자의 병원 선택과 상담 준비에 필요하다. 비용·서류, 검색, 전체 페이지, 개인정보 안내도 사이트 이용에 필요하므로 유지했다. 일반적인 검사 한계와 응급 증상 안내는 환자의 판단에 필요한 내용이다. “병원 소개와 직접 관계없는 개발 문서”와 구분했다.

실제 출처, 개인정보를 입력받지 않는 사이트의 이용 안내, 전화·외부 지도 링크를 유지했다. “자주 궁금해하는”이라는 근거 없는 빈도 표현은 “검사의 목적과 준비 사항”으로 고쳤다. 실제 검토 기록이 없는 상태에서 검토자나 검토일을 새로 만들지 않았다.

## 병행 운영에 맞춘 검색 구조

새 페이지의 canonical은 해당 새 주소를 유지한다. 병원 `MedicalClinic`의 식별자와 대표 URL은 기존 병원 주소에 연결하고, 신규 사이트의 `WebSite`는 “영통탑내과 진료·검사 안내”로 구분한다. 원 사이트를 일괄 301 이전하는 사전 계획은 현재 운영 방향에 적용하지 않는다.

공통 병원 사실의 일관성, 환자가 읽을 수 있는 정적 답변, 문맥에 맞는 출처와 내부 탐색을 유지했다. 이 변경이 특정 AI 모델의 인용률을 높였다는 실측 결과는 없다. [Google AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)는 별도의 특수 최적화를 요구하지 않으며, [canonical 안내](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)는 중복·유사 문서의 대표 URL 판단을 설명한다. 두 문서를 독립 사이트의 색인·인용 보장으로 해석하지 않았다.

## 재발 방지

`public-content-policy.mjs`에서 공개 문구와 파일의 경계를 검사하고, 새 경로에 환자의 필요가 기록되어 있지 않으면 빌드를 거절한다. 검사 범위는 제목·메타 설명·본문·질문·출처·공통 병원 정보·외부 사례 목록을 포함한다. 출력 검사에서는 화면 밖의 직렬화 데이터도 확인한다. 단어 목록만으로 모든 부적절한 기획을 판별할 수 없으므로 페이지 목적과 편집 기준의 검토를 함께 요구한다.

과거 76개 원고를 생성한 일회성 스크립트는 현재 콘텐츠 원장을 덮어쓰지 못하도록 차단했다. 예전 개발·UI 보고서의 76개 검증 기록은 당시 이력으로 남기고, 현재 범위와 실행 절차를 설명하는 README·인수 문서를 갱신했다.

## 검증 범위

구체적인 실행 결과는 [검증 요약](../verification/content-cleanup-2026-09-11/summary.json)에 기록한다. 루트와 GitHub 저장소 하위 경로에서 전체 HTML, 메타데이터, 링크, 색인 지시어, 스크립트 없는 탐색, 사례 원문 연결, 삭제 경로와 내부 파일의 HTTP 404, 접근성·검색·키보드·인쇄 동작을 확인한다.

최종 로컬 검사 결과: 두 경로에서 각각 45개 페이지 정적 감사와 27개 브라우저 검사 통과, 경로별 공개 텍스트 파일 274개 검사 오류 0건, 단위 검사 31개와 Python 하네스 검사 17개 통과, lint·타입 검사 통과. 모바일 Lighthouse는 홈·심장초음파·검색에서 성능 99점, CLS 0을 기록했다. SEO 66점의 미통과 항목은 검토 모드의 의도적인 noindex다. 이 수치를 AEO·GEO 성과로 해석하지 않는다.

실행 환경은 Windows Edge/Chromium이다. 기존 홈페이지의 원문 주소는 수집 원장과 대조했으며, 이번 웹 도구의 원 사이트 요청은 403으로 차단되어 외부 원문 25개의 현재 응답 상태를 재검증했다고 주장하지 않는다. 변경한 Actions 설정의 GitHub 실행·공개 배포는 이번 정리에서 수행하지 않았다. 로컬 결과물은 `web/out/`, 다운로드본은 `artifacts/yeongtong-top-review.zip`이다.

사이트의 내부 공개 조건은 유지한다. 화면의 개발 문구를 제거했다고 의료·운영 승인을 얻은 것으로 처리하지 않았으며, 기본 빌드는 `noindex`다. 이번 정리는 콘텐츠 목적과 구현을 바로잡는 작업이며 외부 AI 인용 성과나 병원의 운영 사실에 대한 신규 인증은 아니다.
