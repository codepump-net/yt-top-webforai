# 최종 영통탑내과 사이트 SEO·AEO·GEO 비교 검토

검토일: 2026-09-11. **내부 조사 보고서이며 병원 사이트에 게시하지 않는다.** 대상은 콘텐츠 정리 후의 로컬 최종 결과물 45개 경로다. 이번 작업에서는 병원 사이트의 원고·화면·검색 공개 설정을 변경하지 않았다.

후속 문서: [AEO·GEO 개선 실행 계획](../aeo-geo-improvement-plan-2026-09-11/README.md) — 기존 국내 Q&A 조사 후보 13개를 활용한 현재 45경로 개선, 병원 확인 항목, 구현·배포 및 레퍼런스 비교 기준.

## 1. 결론과 현재 수준

**기존 영통탑내과보다 기술적 SEO와 정보 접근성은 크게 개선됐다. 두 비교 블로그와 비교하면 가벼운 구성과 일관된 병원 식별이 강점이다. 그러나 답변의 깊이, 실제 의료진의 작성·검토 연결, 병원 운영 사실의 확정은 충분하지 않다. 현재는 잘 정돈된 병원 안내 기반이며, 실전 AEO·GEO 최적화가 완료됐다고 판단할 단계는 아니다.**

| 평가 축 | 현재 판정 | 기존 사례 대비 위치 |
|---|---|---|
| 기술 SEO 구현 | 양호 | 기존 영통탑내과의 메타·제목·본문 구조 문제를 개선. 두 블로그도 원본 HTML·고유 메타가 있어 이 항목은 유사한 기반 |
| 로컬 병원 정보 | 보완 필요 | 전화·주소·운영 안내를 읽기 쉽게 제공. 실제 운영 확인과 구조화 데이터의 시간·좌표 보완 필요 |
| AEO 답변 구조 | 기본 구조 양호, 답변 범위 부족 | 기존 사이트보다 추출하기 쉬움. 두 블로그의 상세 질문·조건·비교 설명보다 얕은 부분이 많음 |
| GEO 출처·전문성 | 기반 구축, 근거·의료진 연결 보완 필요 | 병원 ID 일관성은 강점. 글별 의료진 연결과 직접 근거의 폭은 비교 블로그의 구성에 못 미침. 상대 사이트의 표시가 진실임을 인증하는 평가는 아님 |
| 실제 검색·AI 노출 | 공개 전 / 성과 미측정 | 공개 예정 주소는 404, 로컬 45개 경로는 모두 noindex. 두 블로그 운영 홈과 기존 영통탑내과는 이번 HTTP 표본에서 200 |

이 판정은 관찰 기반의 편집·구현 평가다. 검색엔진 공식 점수, 업계 백분위, 순위·인용 증가율이 아니다. 강점이 공개 불가나 사실 미확정을 상쇄하지 않으므로 가중 평균 100점으로 합산하지 않았다.

### 현재 공개 상태

이번 Node HTTP 요청에서 신규 GitHub Pages 예정 주소는 **404**, 기존 영통탑내과·두 병원 정식 블로그 홈은 **200**이었다. 더건강한365 데모도 이 클라이언트에서는 200이며 `noindex`와 운영 블로그 canonical을 확인했다. 별도 웹 조회 도구는 일부 사이트에서 오류를 반환했다. 특정 클라이언트의 오류를 모든 검색·AI 수집기의 차단으로 일반화하지 않는다.

신규 로컬 출력은 전체 45개 경로 `noindex`, 공개 `sitemap.xml`의 URL **0개**, 내부 계획용 사이트맵은 **43개**다. 검색·404를 제외한 후보 수이며, 실제 색인된 페이지 수가 아니다. GitHub Pages 조회 API도 404를 반환했지만, API 응답만으로 계정 권한과 모든 설정을 확정하지 않았다.

Google AI 검색의 출처 링크 자격에는 색인과 검색 스니펫 노출 가능성이 필요하다. 현재 상태는 신규 사이트의 일반 공개·검색 노출 단계에 도달하지 않았다. 이 결과를 영통탑내과라는 병원 자체가 검색이나 AI에서 전혀 언급되지 않는다는 뜻으로 확대해서는 안 된다. [Google AI 기능의 기술 요건](https://developers.google.com/search/docs/appearance/ai-features#technical-requirements).

호스트 루트 `https://codepump-net.github.io/robots.txt`의 404는 별도로 기록했다. robots 파일 부재 자체를 결함이나 수집 금지로 판정하지 않았다. 저장소 하위 경로의 robots 파일은 호스트 루트의 수집 정책을 제어하지 못한다.

## 4. AEO: 구조의 개선과 답변의 한계

### 강점

검사·진료별 경로에 설명, 준비, 적용 범위와 질문을 정적 HTML로 제공한다. 전화·위치·진료시간은 이미지 OCR 없이 읽을 수 있다. 실제로 전체 페이지를 JavaScript 없이 확인한 검증이 있다. 이전의 제작·검수 대기 설명을 제거해 환자 안내와 AI가 추출하는 텍스트의 목적도 명확해졌다.

### A01. Q&A 75개가 모두 본문의 반복이다

질문이 있는 페이지는 **25개**, Q&A는 **75개**다. 75개 답변 모두 해당 페이지의 본문 블록 문장과 정확히 같다. 21개 상세 페이지는 아래 질문 세 개를 공통으로 쓴다.

- 어떤 검사·진료인가요?
- 방문 전에 무엇을 준비하나요?
- 결과를 볼 때 어떤 점을 확인하나요?

이는 펼쳐보기로 정보를 다시 찾는 데 도움이 될 수 있지만, **75개의 새로운 환자 질문을 해결한 것으로 계산할 수 없다.** 반복 자체를 자동 검색 패널티로 판정하지 않는다. 다만 단독으로 추출된 질문에서 어떤 검사를 말하는지 불명확하고, 목적·준비·한계 외의 실제 궁금증은 충분히 확장되지 않았다.

개선 방향은 각 페이지에서 해결할 질문을 구체화하는 것이다. 예를 들어 심장초음파 페이지에서는 심전도와의 차이, 함께 받는 검사에 따른 준비 확인, 이전 결과 지참, 예약 방법을 각각 답할 수 있다. 답변을 더하려면 기존 근거나 실제 병원 안내를 확인해야 한다. 금식 시간·결과 당일 설명·가격을 추정해서 채우지 않는다.

### A02. 안내는 짧고, 구체적인 운영 답변이 부족하다

진료·검사·검진·건강정보 상세 25개에서 도입문과 본문 블록 텍스트를 합치면 **209~316자**다. 제목·Q&A 중복·출처·공통 UI는 제외한 값이다. 글자 수가 검색 기준이라는 뜻은 아니며, 필요한 질문에 얼마나 답하는지 살펴보기 위한 관측치다.

비교 블로그 표본은 질문을 설명·조건·비교표·연구·FAQ로 확장한다. 현재 결과물은 이해하기 쉬운 기초 안내가 장점이지만, 심화 질문에 인용할 수 있는 정보량은 제한적이다. 해당 블로그들의 설명 정확성은 별도의 문제이며 기존 조사에서 근거 적용과 응급 안내 등의 보완점을 기록했다.

| 환자가 확인하려는 내용 | 현재 제공 방식 | 판정 |
|---|---|---|
| 주소·전화·평소 진료시간 | HTML과 방문 페이지에서 직접 확인 | 직접 답변 가능 |
| 의료진의 전문 분야 | 의료진 목록·개인 프로필 | 직접 답변 가능; 이력의 실제 확인은 별도 |
| 심전도·초음파·홀터의 기본 차이 | 건강정보의 구분 설명 | 기초 답변 가능 |
| 검사 전 약을 스스로 중단해도 되는지 | 임의 중단을 피하고 의료진에게 확인하도록 안내 | 일반 행동 안내 가능 |
| 토요일 점심시간 적용 | 확인 필요 문구 | 실제 운영 사실 미확정 |
| 주차 진입 위치·지원 시간·비용 | 전화 문의 | 사이트 안에서 구체적 답변 부족 |
| 본인의 검사에 해당하는 준비 시간·방법 | 예약별 개별 안내 확인 | 안전한 확인 경로는 있으나 세부 답변 범위 제한 |
| 내시경 총 비용·포함/별도 항목 | 문의 시 확인할 항목 제공 | 정확한 가격 답변 불가 |
| 영문서류 결과지 발급일 | 항목과 제출처를 알려 문의 | 발급 기한 확답 불가 |
| 특정 날짜의 휴진 공지 | 기존 병원 공지 채널 연결 | 병행 운영에서 적절한 연결 제공 |

이 질문들은 편집 검토용이며 빈도 순위가 아니다. 기존 `content/measurement-queries.json`의 20문항도 편집자가 만든 평가 집합이고 `frequencyEvidence`가 null이다. 실제 수요 검증에는 검색 유입 질문이나 개인정보를 제외한 병원 문의 주제 집계가 필요하다.

## 5. GEO: 식별은 개선됐지만 전문성과 근거 연결은 미완성

### G01. 병원 식별은 일관된다

현재 404 제외 44개 페이지가 동일한 `MedicalClinic` ID `https://yttop.co.kr/#clinic`을 사용한다. 비교 블로그는 각각 7개 공통 표본에서 병원 ID 4개가 관찰됐다. 하나의 병원을 글별 다른 객체처럼 기술하던 패턴을 현재 출력에서는 피했다.

신규 `WebSite`와 페이지 주소는 신규 사이트를 식별하고 병원 대표 URL은 기존 홈페이지에 연결된다. 이는 병행 운영 목적에 맞는 설명 구조다. 원 사이트의 현재 schema ID까지 같은 값으로 수정된 것은 아니며, 검색·AI 서비스가 두 사이트를 동일 병원으로 통합했다고 확인한 것도 아니다.

### G02. 실제 의료진과 개별 의료정보가 연결되지 않았다

의료진 프로필은 2개 있으나 진료·건강정보 상세 25개의 출력에서 `author`와 `reviewedBy`는 **모두 0개**다. 본문·관련 안내에서 특정 의사의 프로필로 바로 연결되는 상세 페이지도 **2/25개**다. 단순 프로필 링크는 해당 글의 작성·검토를 의미하지 않는다.

`content/reviews.json`의 실제 검토 기록은 0개다. 구현된 검토 기록 검사 기능과 실제 검토 완료를 구별해야 한다. 비교 블로그의 표본 글 3개씩에는 저자 연결이 있지만, 기존 조사에서 일부 저자 경력 불일치도 발견했으므로 표시만으로 실제 전문성을 인증하지 않았다.

필요한 보완은 의료정보를 실제로 작성하거나 검토한 의료진의 역할·이름·검토일과 해당 프로필을 연결하는 것이다. 이를 위해 별도의 검수 원칙 페이지를 다시 만들 필요는 없다. Google은 독자가 저자를 기대하는 콘텐츠에서 정확한 작성자 정보와 배경을 확인할 수 있도록 권한다. [사람 중심 콘텐츠의 작성자 안내](https://developers.google.com/search/docs/fundamentals/creating-helpful-content#who-how-and-why).

### G03. 외부 의학 근거는 5/25개 상세 페이지, 고유 URL 3개다

현재 상세 페이지 중 병원 외부 출처가 있는 것은 5개다. 고유 의학 출처는 서울아산병원·서울대학교병원의 안내 3개 URL이다. 병원 자체 정보의 출처를 병원 홈페이지로 제시하는 것은 적절하지만, 진단 해석·검사 한계·효과 등의 주장이 모두 외부 근거와 대조됐다는 뜻은 아니다.

현재 출처는 대체로 페이지 아래 참고 자료에 묶여 있다. 독자가 어떤 문장을 어떤 근거로 확인할 수 있는지 더 명확하게 연결할 필요가 있다. 두 비교 블로그는 논문·학회·공공기관 출처를 더 상세히 활용하는 구성이지만, 그중 주장과 맞지 않는 인용도 기존 조사에서 확인했다. **출처 수나 권위 있는 도메인 이름만으로 GEO 품질을 판정하지 않는다.**

병원별 검사 진행·예약·서류 절차는 병원의 확인 자료로, 일반 의학 설명은 해당 주장에 맞는 자료와 의료진 검토로 보완한다. 진단 사례 25개를 원문으로 연결한 현재 방식은 유지하며, 얕은 복제 상세 페이지를 되살려 문서 수를 늘리지 않는다.

### G04. 시간·위치 schema는 두 비교 블로그보다 덜 채워져 있다

현재 `MedicalClinic`에는 이름·전화·주소·이미지·URL·진료 분야가 있으나, `openingHours`/`openingHoursSpecification`, `geo`, `hasMap`은 없다. HTML에는 시간과 지도 링크가 있어 정보가 완전히 사라진 상태는 아니다. 두 비교 블로그에는 시간·좌표·지도 속성이 있으므로 이 항목은 현재 결과물이 더 완성됐다고 평가할 수 없다.

확인한 시간과 위치를 본문과 같은 데이터에서 생성하도록 보완한다. 점심·토요일 적용을 확정한 뒤 조건에 맞게 표현해야 한다. Google LocalBusiness 문서는 영업시간과 위치 등 구체적 정보를 설명하며, 마크업은 실제 내용과 일치해야 한다. [LocalBusiness 안내](https://developers.google.com/search/docs/appearance/structured-data/local-business), [구조화 데이터 품질 지침](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

### G05. 공통 정보의 일관성은 현재 값에서 확인됐으며 변경 전파는 완전하지 않다

전화·시간은 공통 UI에서 `clinic.json`을 사용한다. 그러나 홈의 전화번호와 방문 페이지의 시간은 `content/pages.json`의 소개·설명에도 문자열로 들어 있고, 구조화 주소는 `web/src/lib/site.ts`에 별도로 적혀 있다. 현재 값은 맞지만 한 곳만 바꾸면 불일치가 생길 수 있다.

특히 `operationsReview`는 null이고 토요일 점심·주차 지원 등은 미확정이다. 데이터 구조를 만들었다는 사실과 운영 사실의 검증 완료를 같게 평가할 수 없다. 원장의 주소·시간을 바꿨을 때 화면, 메타 설명, JSON-LD가 함께 갱신되는지 검사가 필요하다.

## 6. 기존 홈페이지와 동시에 운영할 때의 과제

신규 사이트는 환자가 필요한 정보를 이해하고 방문하도록 돕는다. 기존 사이트의 공지와 진단 사례를 연결한 구조는 목적에 맞는다. 이 구조에서 다음 세 가지를 함께 관리해야 한다.

1. **양쪽 정보의 일치:** 기존 `/MAIN2`나 검사 항목 충돌 등 앞선 조사에서 발견한 정보가 남아 있는지 확인한다. 새 사이트 정리만으로 원 사이트의 과거 정보가 사라지지는 않는다. 현재 원 사이트 전체를 다시 수집하지 않았으므로 모든 문제가 계속 남아 있다고 단정하지 않는다.
2. **독립적인 답변 가치:** 신규 페이지에는 환자에게 필요한 설명·준비·상담 정보를 제공하고, 같은 원문을 재게시하는 페이지는 늘리지 않는다. 기존 사이트에서 신규 안내로 연결할 공식 탐색 경로도 확인한다.
3. **대표 URL과 성과의 구분:** 독립 안내는 자기 canonical을 사용하되 실질적 복제 문서가 생기면 대표 URL을 따로 판단한다. 현재 canonical은 구현상 일치하지만 Google이 선택한 canonical은 미확인이다. [Google canonical 안내](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

현재 관측 도구는 설정한 신규 사이트 URL 한 곳의 인용률을 계산한다. 병행 운영에서는 **신규 URL 인용, 기존 URL 인용, 둘 중 하나 인용, 병원명 언급**을 별도로 보아야 한다. 기존 사이트 인용 증가를 신규 사이트의 직접 인용으로 합산하지 않는다.

## 7. 다음 개선 우선순위와 완료 조건

우선 기존 페이지를 보완한다. 병원 목적과 무관한 정책·개발 페이지 추가, 지역·증상 키워드만 바꾼 대량 페이지, 검증되지 않은 빈도·성과·치료 수치는 개선 항목에 넣지 않는다.

FAQPage schema가 없는 것은 이번 비교의 감점 항목이 아니다. Google은 2026년 5월 7일부터 FAQ 리치 결과를 중단했다고 공지했다. 질문·답변 본문의 유용성은 별도로 평가한다. `llms.txt`나 많은 schema 유형도 최적화 점수로 합산하지 않는다. [Google 공식 변경 이력](https://developers.google.com/search/updates), [AI 기능 안내](https://developers.google.com/search/docs/appearance/ai-features).

## 8. 성과를 확인할 측정 방법

현재 SEO·AEO·GEO 결과 수치는 **미측정**이다. 0% 성공으로 처리하지 않는다. 비교 사이트들도 실제 검색 유입과 AI 인용 자료가 없어 효과 순위를 매길 수 없다.

- SEO: 공개 후 Search Console·네이버 서치어드바이저에서 수집·색인·선택 canonical을 확인하고, 브랜드/비브랜드·지역/검사 질문별 노출과 클릭을 기록한다. 등록 태그나 사이트맵 제출만으로 색인 완료로 처리하지 않는다.
- AEO: 기존 평가 질문 20개에 이번에 드러난 주차·시간 예외·검사 준비·발급 조건 질문을 보강한다. 목표 페이지가 있다는 사실 대신, 답변에 대상·조건·예외·행동이 남아 있는지 검토한다. 실측 빈도와 편집 선정은 구분한다.
- GEO: 동일한 질문·서비스·언어·관측 기간으로 URL 인용과 병원명 언급을 구분한다. 신규/기존 도메인 각각과 합집합을 기록한다. 요청 오류 수, 유효 답변 수, 사람의 사실 확인 여부를 남긴다.
- 비교: 공개 시점의 기준선과 후속 기간을 비교하되 모델·질문·콘텐츠 변경일을 함께 기록한다. 신규/기존 사이트의 총 인용이 어떻게 변했는지 확인하고, 단순 전후 변화만으로 인과관계를 확정하지 않는다.

이 보고서의 범위는 최종 로컬 구현과 공개 표본의 비교다. 실제 의료진의 검수 수행, 병원 운영 사실 전체, 모든 외부 글의 의학적 정확성, 검색 관리자 계정, 실제 AI 서비스의 반복 답변은 확인하지 않았다.

재현: 저장소의 `web/`에서 `node scripts/seo-review.mjs`. 현재 로컬 조사 원장과 `out/`, `reports/build-manifest.json`이 필요하며 공개 빌드나 사이트 콘텐츠를 수정하지 않는다.
