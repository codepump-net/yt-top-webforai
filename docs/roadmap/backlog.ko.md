# 운영·개발·확장 백로그

기준일: 2026-11-16. 아래 항목은 저장소 분석에 따른 **후속 제안**이며 구현 완료·확정 일정·자동 실행을 뜻하지 않는다. 실제 운영 문제와 사용자 필요에 따라 우선순위를 바꾼다.

## 1. 우선순위 기준

P0는 실제 운영 장애·잘못된 정보·공개 근거 문제처럼 발견 즉시 대응할 사안이다. 이 문서만으로 새 P0 장애가 확인되었다고 주장하지 않는다. P1은 다음 유지보수 주기, P2는 필요·편익을 확인한 구조 개선, P3는 별도 제품 착수 조건이 필요한 확장이다.

## 3. 권장 진행 묶음

1. **운영 기준 정착:** B01·B05·B07·B08·B11. 실제 자료와 현행 동작을 먼저 정리한다.
2. **기능 개발 단순화:** B04·B06 후 B02·B03·B10. 구조 변경은 기능 하나씩 출력 보존을 확인한다.
3. **수요가 입증된 확장:** B09·B12. 계정·콘텐츠·검토·보관·운영 책임이 준비된 범위만 착수한다.

강의의 한 과제에는 위 작업 전체를 주지 않고 독립 검토 가능한 하위 작업 하나를 사용한다. 작업 카드마다 근거·변경 전후·완료 조건·검증을 적는다.

## 4. 확장 제안에서 별도 판단할 일

온라인 예약·환자 계정·검사 결과 업로드·결제·자동 의료 상담은 현재 정적 앱의 작은 기능 추가로 취급할 수 없다. 실제 필요가 확인되면 별도 데이터·인증·보관·오류·운영 설계를 작성한다. 현재 요청의 구현 범위에는 포함하지 않는다.

기존 `yttop.co.kr` 수정, 환자용 SEO 보고 페이지, 분석 동의 팝업·설정 버튼, 의료 승인·빈도·성과 생성은 이 백로그의 할 일로 만들지 않는다.
