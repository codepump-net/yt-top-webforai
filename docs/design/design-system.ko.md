# 디자인 콘셉트와 UI 규칙

기준일: 2026-11-16. 기존 구현을 설명하는 현행 기준이며 새로운 디자인 시안을 적용한 기록은 아니다.

## 1. 콘셉트

**차분하게 읽고 필요한 안내를 찾는 건강백과.** 실제 병원 운영자 정보를 분명히 하되, 안내 제목·본문·준비 행동이 먼저 보이게 한다. 녹색과 흰색·옅은 종이색, 충분한 행간, 단순한 카드와 섹션 경계가 현재 시각 언어다.

| 원칙 | 화면에서의 적용 |
|---|---|
| 읽기 우선 | 긴 원고의 제목·요약·목차·본문·질문·출처 구분 |
| 다음 행동 명확 | 검사 준비, 관련 안내, 전화·지도 연결 |
| 근거와 사실성 | 실제 병원 사진·근거 있는 프로필·출처·날짜 |
| 방해 없는 탐색 | 통계 팝업·배너·설정 UI 없음, 강제 회원가입 없음 |
| 접근성 | HTML 의미 구조·키보드·초점·인쇄·감소된 모션 |

## 2. 스타일의 실제 소유 위치

`globals.css`를 먼저 로드하고 `library.css`가 건강백과의 읽기·카드·목록 스타일을 보완한다. Tailwind 4를 사용하지만 주요 화면은 공통 CSS 클래스도 함께 사용한다. 토큰과 실제 적용값을 확인하고 새 화면마다 유사 클래스를 중복 만들지 않는다.

| 토큰·값 | 위치·용도 |
|---|---|
| `--ink: #183b37` | 기본 글자·진한 녹색 |
| `--brand: #125b51` | 주요 버튼·브랜드·링크, themeColor |
| `--muted: #586760` | 보조 본문 |
| `--line: #dce5de` | 기본 경계 |
| `--cream: #f6f7f2`, `--pale: #edf3ed` | 섹션·완충 배경 |
| `--library-line: #dce5e0`, `--library-paper: #f7f9f7` | 홈 건강백과 보완 토큰 |
| `--radius: 18px` | 기본 토큰. 건강백과 카드는 실제로 약 8~10px 보완값 사용 |
| 초점 `#956306`, 3px outline | `:focus-visible`로 탐색 위치 표시 |

폰트는 Pretendard → Noto Sans KR → 플랫폼 한국어 폰트 → sans-serif 스택이다. 스택에 이름이 있다고 별도 웹폰트를 다운로드하는 것은 아니다. 기본 본문 17px·행간 1.75, 상세 본문은 보완 스타일에서 18px·1.95, 좁은 화면은 17px로 조정한다. `.container`는 최대 1260px이며 화면별 여백 규칙을 따른다.

## 3. 화면 패턴

| 패턴 | 구조 | 소유 컴포넌트 |
|---|---|---|
| 홈 | 제품·운영자 → 검색·주요 안내 → 환자 목적 → 분야·방문·공지 | `content.tsx`의 `Home`, `HomeSearch` |
| 허브 | 제목·요약·분야 이미지 → 그룹·카드·탐색 | `HubDirectory`, `Cards`, `Search` |
| 상세 | 브레드크럼 → 제목·요약 → 목차·본문 → 관련 안내·출처 | `PageContent`, `ArticleNavigation`, `ArticleFooter` |
| 검색 | 입력 → 분야 → 결과 수·목록 → 결과 없음·복구 | `Search`, `SiteSearch` |
| 공지 | 기간·기준일 → 목록·필터·쪽 나누기 → 상세·첨부 | `NoticeBoard`, `NoticeDocument` |
| 병원·방문 | 실제 정보·사진·의료진·시간·전화·지도 | `DoctorCards`, `VisitInfo` 등 |

홈의 주요 안내 12개는 정적 `<a>` 링크다. 검색이나 슬라이더에만 넣지 않는다. 카드 전체 링크에는 의미 있는 제목을 넣고 임의의 이동 애니메이션을 추가하지 않는다.

## 4. 반응형·입력·초점

주요 보완 분기점은 1100px·850px·600px이다. 일반 카드는 3→2→1열, 본문 옆 목차는 넓은 화면의 사이드 영역에서 작은 화면의 문서 흐름으로 바뀐다. 상세 내부 카드 그리드는 넓은 화면에서도 2열일 수 있다.

헤더·모바일 연락 영역 높이는 `SiteNavigation`이 측정해 앵커·초점이 가려지지 않게 보강한다. 모바일 메뉴는 native `<details>`와 Escape·외부 입력·초점 이동 처리를 사용한다. 창 크기만 보지 말고 긴 메뉴명·번역·키보드 이동을 확인한다.

이미지 확대는 사용자가 누른 경우에만 `<dialog>`를 열며 닫으면 원래 링크로 초점을 돌린다. 통계용 팝업 금지와 사용자가 선택한 자료 확대는 목적이 다르다.

## 5. 접근성·이미지·인쇄

- 페이지 제목 h1 하나, h2·h3 위계, 본문 바로가기와 명시적 입력 label을 유지한다.
- 검색 결과 수는 `aria-live`, 필터는 `aria-pressed`, 현재 탐색 위치는 `aria-current`로 전달한다.
- 표는 caption·th를 유지하고 필요한 표 영역 안에서만 가로 스크롤한다.
- 사진·도해는 width·height·alt·출처를 확인한다. 장식·실루엣을 실제 인물 사진으로 설명하지 않는다.
- 본문·질문 답변은 이미지로만 제공하지 않는다. 인쇄에서는 목차·도구를 정리하고 질문 답변이 접혀 유실되지 않도록 한다.
- `prefers-reduced-motion`과 작은 화면의 터치·초점을 유지한다. 자동 검사 결과와 실제 가독성 검토를 함께 사용한다.

## 6. 변경 검토표

| 변경 | 확인할 대표 화면 |
|---|---|
| 토큰·기본 글꼴 | 홈·긴 의료 안내·의료진·비자 번역 |
| 카드·그리드 | 홈·질환백과·진료분야·검색 결과 |
| 헤더·목차 | 모바일 메뉴·긴 페이지 앵커·키보드 초점 |
| 이미지 | 원본 종횡비·확대·저해상도·OG·문서 PNG |
| 인쇄 | 준비 안내·표·접힌 FAQ의 답변 |

새 기능은 [기능 명세](../features/README.md)의 상태·실패·접근성 조건을 먼저 정하고 이 패턴을 재사용한다.
