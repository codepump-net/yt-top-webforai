# 0001. 현행 문서와 날짜별 증거를 분리한 docs 구조

상태: 일부 대체. 결정일: 2026-11-16. 범위: 이번 개발 분석·운영·교육 문서 정리. 날짜별 폴더의 보관 위치는 후속 요청에 따라 [0002](0002-client-request-collection.ko.md)로 대체한다.

## 배경

기존 `docs/`는 날짜별 원고 반영·감사·배포 기록이 풍부하지만 신규 개발자가 현행 목표·사이트맵·기능·개발 경계를 한 흐름으로 읽기 어렵다. 45·76·108개 경로와 당시 review 배포 설명은 역사적 사실이지만 현재 135개 원장·현재 main production 규칙과 구분해야 한다.

## 선택지와 결정

기존 자료 전체 이동은 링크·증거 경로를 깨뜨릴 수 있고, 새 장문 문서 하나만 추가하면 기능별 운영이 어렵다. 따라서 **기존 날짜별 폴더는 보존하고, 주제별 현행 문서·기능 명세·강의 보조자료와 상위 색인을 추가**한다.

`docs/README.md`를 진입점으로, `features/`를 기능별 개발 기준으로 사용한다. 원장과 분류에서 수치·경로·주 담당 기능을 생성해 수동 복사를 줄인다. 기존 인수·콘텐츠 README에는 현행 문서와 역사적 구간을 구분하는 안내를 넣는다.

## 결과와 검증

원장·앱·사이트 UI·출판 근거는 이번 문서 정리의 변경 대상이 아니다. docs 도구는 docs의 생성 문서만 갱신한다. 코드 기반 분석과 실제 운영 실측·강의 원본을 구분하며, 아직 없는 관리자 앱을 구현 완료로 표시하지 않는다.

상대 링크·원장 대응·생성물 일치·사이트 출력 경계를 확인한다. 문서 CI 도입·향후 코드 분리는 별도 백로그로 진행한다. 기능 수가 늘거나 CMS·운영자 앱이 실제로 생기면 구조와 책임을 재검토한다.
