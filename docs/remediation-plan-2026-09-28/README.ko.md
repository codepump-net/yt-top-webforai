작성일: 2026-09-28. 기준 커밋: `e27a4c4`. [최종 검토](../final-session-review-2026-09-28/README.ko.md)에 대한 후속 작업 계획이다. 이번 산출물은 수정할 내용과 완료 기준을 정한 것이며, 원고 수정·의료 확인·검색 공개가 완료됐다는 기록은 아니다.

**15개 작업 묶음에 기존 미해결 검토 항목 138건을 모두 연결했다.** 139건 중 안내도 캡션 항목 F129는 해결 상태를 유지하고 재발 여부만 확인한다. 작업 묶음 수와 오류 문장 수는 다르다. 기존 검토에 더해 원본 안내도와 HTML 대응, 페이지 목적·검색 설명 일치, 확인 정보·의료 검토, AEO·GEO 관측을 독립 작업으로 명시했다.

바로 편집할 수 있는 것은 본문에 이미 있는 사실을 활용한 FAQ·도입·요약, 어색한 문맥, 중복 설명이다. 새 의료 기준은 개발자가 공식 근거를 먼저 확보하고 의료 검토로 연결한다. 본원만 확정할 수 있는 운영 정보는 최소 확인 항목으로 분리한다. 두 지역 지원사업의 현재 참여 여부는 사용자의 ‘확인 필요’ 답변을 유지한다.

제공 이미지 17개는 그대로 사용한다. 이미지의 문구·로고·배치를 바꾸거나 새로운 그림을 제작하지 않는다. 원본 작은 글자와 본문 사이의 차이는 HTML 정보 보완으로 처리한다. 신장 배너 오기 정정은 별도 지시가 필요한 상태로 기록하며 다른 편집 작업의 선행 조건으로 삼지 않는다.

각 작업에 연결된 기존 검토 ID, 원문 위치, 현재 문구, 수정 방향은 [작업 원장 CSV](work-register.csv)와 [상세 JSON](work-register.json)에 있다. E01~E11은 기존 138건의 주 담당 작업을 중복 없이 배정했다. E12~E15는 모든 해당 작업을 지원하는 후속 검증·확인·관측 작업이다. 이미지·출처 등 여러 작업에 걸친 내용은 주 담당자가 변경하고 연관 작업에서 같은 결과를 참조한다.

E12에서는 전체 129개 페이지의 환자 목적도 다시 읽는다. 그중 도입·검색 설명을 그대로 사용한 102개는 목적과 검수 기준을 독립적으로 판단한다. 같은 문장이라는 이유만으로 자동 교체하지 않고, 환자가 무엇을 이해하거나 결정해야 하는지와 실제 답변의 위치를 적는다. 예를 들어 채용검진의 목적은 ‘문의 방법을 안내’가 아니라 ‘필요한 준비물과 발급기간을 알아 제출 일정을 잡는 것’으로 구체화한다.

E15에서는 신규 증상 20편마다 제목에 대응하는 기본 평가 질문을 만들고 현재 53개 질문과 중복·목적을 대조한다. 글 수에 맞춰 중복 질문을 유지할 필요는 없지만 20개 경로의 평가 대응은 모두 남긴다. 각 질문에는 `해당 페이지 / 답에 반드시 있어야 할 사실 / 적용 조건 / 잘못 단정하면 안 되는 내용 / 판정 근거`를 둔다. 실제 관측에는 동일한 질문·모델·검색 모드·언어/지역·대화 문맥을 기록하고 오류와 무응답을 따로 센다. 검색 공개 전에는 콘텐츠 답변 충족 여부만 평가하며, 공개 후 Search Console 자료와 실제 AI 답변·출처 URL을 수집한 경우에만 노출 결과를 기록한다.

‘문의하세요’라는 단어 자체를 금지하지 않는다. 확인된 사실은 먼저 제공하고, 제출기관의 인정 조건·실제 예약별 일정·미확인 지원 조건처럼 필요한 차이만 뒤에 설명한다. 응급 증상은 먼저 행동을 안내한다.

**초기에 바로 착수할 범위**

첫 편집 묶음은 채용·결핵·비자검진, 홀터·심장초음파·경동맥초음파·복부초음파, 방문 안내, 협심증 치료다. 기존 본문에 있는 답을 도입·FAQ·검색 요약에 연결하는 작업부터 한다. 이와 함께 5개 안내도 대조표와 C01~C15 확인 원장을 준비한다. 운영 답변을 기다리는 동안에도 기존 정보의 편집은 진행한다.

두 번째 묶음은 내시경 준비·회복의 조건 정리와 증상·질환 40편, 나머지 진료 원고다. 근거 확인이 필요한 설명은 확인 자료와 함께 초안을 만들고, 공통 하단·관련 링크·이미지 설명까지 같은 독서 흐름에서 검토한다. 공지·예방접종은 공식 대상과 날짜를 먼저 구체화하고 본원 참여 여부는 확인 상태를 유지한다.

세 번째 묶음은 수정된 한국어 원고에 맞춘 외국어 대조, 전체 요약·검색·FAQ 데이터 일치, 실제 검토 기록과 출력 검증이다. 검색 공개 조건과 노출 관측은 이 콘텐츠 작업의 완료 상태에 따라 따로 판단한다. 통합·이식·배포 절차나 기존 병원 게시판에 새 글을 게시하는 작업은 이번 명세에 추가하지 않았다.

**완료 판정 방식**

| 확인 단계 | 통과 기준 | 남길 증거 |
|---|---|---|
| 개별 문구 | 질문이 요구한 답이 있고 기존 사실을 문의 지시로 대체하지 않음. 임상·운영 차이는 적용 조건으로 설명 | 원문 위치, 변경 전후, 해당 검토 ID, 필요하면 유지한 이유 |
| 페이지 | 제목·첫 답변·표/본문·예외·다음 행동이 같은 환자 목적을 해결. 응급 페이지는 행동 우선 | 페이지별 독자 목적과 실제 답변 위치. 40편은 별첨 명세와 대조 |
| 이미지 | 원본 보존과 HTML 정보 대응을 둘 다 충족 | 원본 픽셀 검사와 별도의 내용 대응표, 모바일/PC 확인 |
| 출처·사실 | 추가 주장·수치·운영 정보에 유효한 근거와 적용 조건이 있음 | 출처 확인일, C 항목 결과, 실제 편집본의 검토 상태 |
| 사이트 출력 | 수정된 제목·본문·FAQ·검색·구조화 데이터 일치. 원래 링크·이미지·사례 제외·검토 모드 유지 | 기존 콘텐츠 검사·정적 출력 검사·관련 단위/브라우저 검사. 렌더러 변경 시 해당 기능 회귀 확인 |
| AEO·GEO 관측 | 정답 정확성과 실제 인용·유입을 나누어 기록 | 질문 집합 버전, 도구/모델·검색 모드·시각·지역/언어·문맥, 실제 답변·인용 URL과 오류 |

기존 검토 항목의 종료 상태는 `수정 완료`, `검토 후 유지`, `사실 확인 대기`, `판단 대기`로 기록한다. ‘검토 후 유지’에는 환자에게 필요한 이유와 근거를 남긴다. 실제 문구를 읽어 해결 여부를 판단하며 특정 단어 감소·문장 길이·페이지 수·검사 통과만으로 종료하지 않는다. 구조가 달라진 경우에 필요한 회귀 검사만 보강하고 문장을 그대로 따라 쓰는 테스트를 대량 추가하지 않는다.

현재 `review/noindex`는 콘텐츠 검토 전 유지하는 상태다. 본원 검토를 사실대로 기록하고 기존 공개 검증이 충족된 이후에 검색 공개 조건을 재검토한다. 콘텐츠 편집 때문에 승인 기록이나 의료진 이름을 자동으로 생성하지 않는다.

Google이 설명하는 생성형 검색의 기본 방향도 유용한 내용과 기술적 접근성이다. 이 명세의 AEO 작업은 직접 답변·조건·행동을 충실히 쓰는 것이고, GEO 작업은 병원 사실·출처·본문과 메타데이터의 일치를 유지하는 것이다. 특수 파일이나 마크업 개수를 늘리는 것을 완료 조건으로 사용하지 않는다. [Google 공식 안내](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).
