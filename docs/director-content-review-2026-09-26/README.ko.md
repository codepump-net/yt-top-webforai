# 2026-09-26 원장님 자료 대조 검토 및 적용 계획

**후속 지시 반영:** 사용자가 영문 URL로 원고를 적용하도록 확정했다. 한글 URL 검증 확장은 범위에서 제외했으며 현재 적용 결과는 [구현·검증 기록](implementation.ko.md)을 따른다. 아래의 현황 수치는 최초 검토 시점의 비교 기준이다.

검토 대상: `plan/`의 01~04번 문서와 「영통탑내과 독립질환백과 심장·혈관 20편」 DOCX. 이 문서는 내부 작업 계획이며 홈페이지에 게시하지 않는다. 이번 작업은 검토와 계획 수립까지이며, 홈페이지 원고·코드·배포 상태는 변경하지 않았다.

**권장 범위는 심장·혈관 질환 20편 추가, 기존 검사 정보 갱신, 백과 분류 정리, 공통 하단 안내 구현이다.** 기존 74개 경로를 보존하면서 20개를 추가하면 94개 경로가 된다(404 포함). 기존 협심증·판막 해설은 별도로 유지하며, 추가 증상 원고나 별도 혈압검사 페이지는 이 수치에 포함하지 않는다.

실제 배포 사이트도 두 페이지를 표본 확인했다. [질환백과](https://codepump-net.github.io/yt-top-webforai/diseases/)는 기존 안내 15개, `noindex`이며 신규 `/diseases/cardio/` 링크가 없었다. [심장 표지자 검사](https://codepump-net.github.io/yt-top-webforai/services/heart/cardiac-markers/)에도 기존 즉시검사 안내가 남아 있었다. 이는 전체 배포 상태를 다시 검증한 결과는 아니다.

자료 적용 순서는 **03의 명시적 수정 → 01·02·04의 세부 규칙 → DOCX 본문**으로 잡는다. 다만 검토일·검토자·게시 승인은 단순 문구 치환과 구분한다. 원고에 명시된 작성·검토자와 날짜는 내부 근거로 보존하고, 수정한 웹 편집본의 실제 확인 범위를 기록한다.

### 2-1. 검사 정보의 구체적 수정

03번 문서에 따른 목표 사실은 다음과 같다. 이는 원장님 제공 운영 자료를 반영하는 것이며, 이번 검토에서 병원의 실제 검사 운영을 별도로 인증한 것은 아니다.

| 검사 | 반영할 안내 |
|---|---|
| Troponin I | 시행 가능, 원내 약 20분 |
| CK-MB | 시행 가능, 일반적으로 다음 날 |
| Troponin T | 시행 가능, 일반적으로 다음 날 |
| CPK | 시행 가능, 일반적으로 다음 날 |
| D-dimer | 시행 가능, 일반적으로 다음 날 |
| NT-proBNP | 시행 가능, 일반적으로 다음 날 |
| IMA | 향후 도입 예정, 현재 시행 검사에 포함하지 않음 |
| CART BP Pro | 반지형 24시간 활동혈압검사, 장비 반납 후 약 1시간 내 결과 확인 |

**‘원내 즉시검사가 아님’과 ‘검사를 시행하지 않음’은 다르다.** 기존 문장을 모두 틀린 정보로 취급하지 않고, 시행 가능 항목과 소요시간을 명확히 덧붙인다. 03에 없는 BNP 자체의 시행 여부나 5개 검사의 원내·위탁 구분은 임의로 정하지 않는다. 모든 검사가 20분 내 나온다는 표현으로 확대하지 않는다.

직접 수정할 주요 페이지:

- `/services/heart/cardiac-markers/`: 제목 범위, 요약, 검사별 설명·예상시간 표, FAQ 수정. D-dimer·CPK 등을 모두 심장 손상 전용 검사로 설명하지 않도록 검사별 목적을 구분한다.
- `/services/examinations/`: 심장검사 목록, 결과시간 표, 활동혈압 안내를 갱신한다. `ambulatory-blood-pressure` 같은 안정적인 본문 앵커를 추가해 관련 글에서 바로 연결한다.
- `/services/heart/`, `/conditions/heart-disease/`, `/conditions/`: 새 검사 안내를 요약하고 상세 검사 페이지로 연결한다. 모든 진료에 여섯 항목이 일괄 필요하다는 인상을 주지 않는다.
- `/conditions/chronic-disease/`: 가정혈압 기록과 활동혈압검사의 관계를 안내하고 새 고혈압·이상지질혈증 글로 연결한다.
- `/health/angina-treatment/`: 기존 치료 FAQ 역할을 보존하고 안정형 협심증 글 및 최신 검사 안내를 연결한다.
- 신규 20편: ‘영통탑내과에서는 어디까지 평가하나요?’를 질환별 필요에 맞게 편집한다. 심부전 원고의 ‘BNP 계열 검사는 외부검사 또는 상급병원 평가’는 NT-proBNP 시행 안내와 맞춰 수정한다.

활동혈압검사는 우선 기존 검사 안내의 별도 항목으로 추가한다. 준비·착용·반납 등 독립적인 환자 안내가 충분히 확보되면 별도 페이지를 후속 검토할 수 있다. 현재 원고만으로 가격, 착용 제한, 방수 성능이나 예약 정책을 덧붙이지 않는다.

### 2-2. 공통 하단 안내

`ArticleFooter`와 같은 공통 컴포넌트를 만들고, 카테고리 표시 문자열 대신 페이지의 역할·주제·언어 메타데이터로 적용한다. 본문의 검사 한계와 개별 응급 안내는 유지한다.

| 페이지 범위 | 병원 안내 | 일반 안전문 | 심장 예약 | 서류 안내 |
|---|---|---|---|---|
| 증상·질환·진료분야·검사·시술 글 | 적용 | 적용 | 심장 관련 글에 적용 | 미적용 |
| 암환자 지지진료·예방접종 | 적용 | 적용 | 미적용 | 미적용 |
| 국가검진·채용·공무원·비자·결핵 | 적용 | 적용 | 미적용 | 적용 |
| 마약검사·영문서류 | 적용 | 적용 | 미적용 | 서류 목적에 따라 적용 |
| 비용·서류 안내 | 필요한 범위 | 비용 안내만으로 적용하지 않음 | 미적용 | 적용 |
| 의료진·오시는 길·공지·개인정보 | 필요한 범위 | 미적용 | 기존 방문 안내의 필요한 위치 | 필요한 범위 |

일반 푸터에는 최소 병원 식별 정보를 남기고, 상세 진료시간·주차·접수·예약 정책은 각 페이지에 한 번만 제공한다. 주소·전화·시간을 20개 본문에 복사하지 않는다. 접이식 병원 정보 패널은 키보드로 조작할 수 있게 하고, 응급 안내는 접힘 여부와 관계없이 보이게 한다. 기존 좌측 목차와 모바일 목차·인쇄 동작을 유지한다.

기존 영어·중국어·태국어·러시아어·네팔어 비자 안내도 영향을 받는다. 언어별 공통 안전·서류 문구를 준비하고 확인한다. 한국어 패널을 다섯 번역 페이지에 일괄 삽입하지 않는다. 국가검진 안내의 ‘제출기관 원본 양식’은 제출용 서류가 필요한 경우라는 문맥을 분명히 한다.

| `angina-treatment` / 협심증의 약물치료와 스텐트 | 기존 URL·본문 유지. 안정형 협심증의 관련 FAQ 글로 연결 |
| `heart-valve-regurgitation` / 심장판막 역류와 치료·추적검사 | 기존 URL·본문 유지. 승모판 역류·대동맥판 협착의 관련 해설로 연결 |
| `palpitations-followup`, `abdominal-pain`, `fever-during-cancer-treatment` | 증상 중심 글로 유지. 실제 내용이 있는 부분에서 원인 질환·응급 안내로 연결 |
| `liver-disease` / 반복되는 간수치 상승과 간질환 | 추가 정리 권고: 검사 이상·진료분야 성격이므로 증상 목록에서 제외하고 간질환 관련 안내로 배치 |
| `gallstones`, `influenza`, `covid-19`, `thyroid-cancer-surveillance` | 해당 질환의 기존 안내 유지. 새 카테고리와 역할 표시를 맞춤 |
| `colon-polyp-followup`, `obesity-medication`, `cancer-family-history` | 기존 추적검사·치료·가족력 안내 유지. 질환 정의 글과 구분해 관련 해설로 표시 |

관련 FAQ·해설은 ‘질환 설명’과 시각적으로 구분한다. 기존 원고를 질환별 새 글로 오인하게 하거나, 신규 20편과 합쳐 기존 URL을 폐기하지 않는다. **백과 목록에서 제외하는 것은 페이지 삭제가 아니다.** 사이트 전체 검색·전체 페이지와 해당 진료분야의 연결은 유지한다.

검색은 구 카테고리명과 02의 aliases를 실제 검색 대상으로 포함한다. 현재 검색기는 별칭 필드가 없고 카테고리 문자열을 검색 본문에 포함하지 않으므로 필터 이름만 바꿔서는 충족되지 않는다. 필터 순서는 검색 결과의 가나다순에서 유도하지 않고 02의 순서를 따른다.

‘신장’ 등 대응 글이 없는 분류는 설정에 남기고 0개 상태를 일관되게 표시한다. 빈 분류를 채우기 위해 무관한 진료 글을 넣거나 새 페이지를 자동 생성하지 않는다. 전체 글 수·필터별 글 수·검색 결과 수를 실제 목록에서 계산하고, 관련 해설을 포함한 수와 질환 설명 수의 의미를 혼동하지 않게 한다.

## 4. DOCX 20편의 편집과 링크

20편 모두 신규 독립 질환 페이지로 만든다. 개별 대상·URL·기존 글과의 관계·중점 검토 항목은 [20편 적용표](article-mapping.ko.md)에 정리했다. 원고에 있는 핵심 답변, 정의, 원인, 증상, 진단, 치료, 위험 신호, 생활관리, 병원 평가 범위, 의뢰 기준, FAQ를 기존 본문·목차 구조에 대응시킨다.

게시 전에 필요한 편집:

1. **운영 정보 갱신:** DOCX에 반복된 Troponin I 중심 안내를 03의 수정 사항과 조정한다. 하단 병원 정보·안전문은 01의 공통 컴포넌트로 옮긴다. DOCX에는 예약 공통문과 CART BP Pro가 없으므로 따로 보완한다.
2. **내부 설명 제외:** 20편에 반복된 ‘서울아산병원 질환백과는 … 내부 인덱스로만 참고…’ 문단은 제작 과정 설명이므로 내부 원장에만 보존한다. 권장 URL·카테고리·메타 설명 라벨도 본문이 아닌 데이터로 옮긴다.
3. **오탈자 교정:** ‘승모판 역류이란 → 승모판 역류란’, ‘승모판 역류은 → 승모판 역류는’, ‘대동맥류·대동맥박리이란 → 대동맥류·대동맥박리란’, ‘…박리은 → …박리는’을 제목·소제목·요약까지 점검한다. 원고 URL은 조사 교정 때문에 바꾸지 않는다.
4. **응급 문맥 편집:** 급성 심근경색 글의 공통 결론 ‘안정적인 경우 영통탑내과에서 초기 평가와 추적관리’는 급성 의심 상황과 회복 후 관리를 구분해 다시 쓴다. 대동맥류·대동맥박리 역시 안정된 대동맥류 추적과 급성 박리 대응을 분리한다. ‘5분 이상’이라는 문구가 도움 요청 전 반드시 기다리라는 뜻으로 읽히지 않게 편집한다.
5. **질환별 문장 확인:** 각 글에 반복된 ‘검진에서 우연히 발견’, ‘생활요법·시술·수술 조합’ 등 일반 문장을 질환별 상황에 맞게 점검한다. 병원이 실제 시행하는 검사와 상급병원에서 시행하는 검사를 명확히 구분한다.
6. **참고자료 구체화:** 모든 글에 동일하게 들어간 AHA·ESC·WHO의 대분류 링크는 개별 치료·검사 설명의 직접 근거로 부족하다. 질환별 공식 상세 자료를 선정하고 관련 본문·FAQ와 연결한다. 참고 출처와 병원 운영 사실의 근거를 구분한다.
7. **FAQ 명칭 정리:** 원고의 질문 60개를 보존하되 실제 빈도 조사 자료가 없는 ‘자주 묻는’ 표현은 현행 사이트처럼 ‘질문과 답변’으로 표시한다.

응급 안내 편집의 참고로 AHA는 심근경색 경고 신호가 있으면 도움 요청을 지체하지 않도록 안내하며, MedlinePlus는 초기 정상 트로포닌 결과만으로 판단하지 않고 증상·다른 검사와 함께 해석하도록 설명한다. [AHA 심근경색 경고 신호](https://www.heart.org/en/health-topics/heart-attack/warning-signs-of-a-heart-attack), [미국 국립의학도서관 트로포닌 검사](https://medlineplus.gov/lab-tests/troponin-test/). 이번 계획 검토는 20편 전체의 의학적 승인이나 모든 참고자료의 검증을 완료한 것은 아니다.

### 관련 링크의 현실적인 범위

03은 글마다 관련 증상 3~5개, 검사 2~4개, FAQ 1~3개를 요구한다. 현재는 흉통·호흡곤란·어지럼·실신·다리부종 등 개별 증상 페이지가 충분하지 않고, DOCX의 ‘함께 확인할 증상’은 글 제목이 아닌 일반 텍스트 목록이다.

- 증상명은 원고대로 제공하되 존재하는 증상 글 또는 실제 해당 내용을 다루는 본문 앵커가 있을 때 링크한다. 진료 허브로 연결할 때는 ‘심장질환 진료’처럼 목적지를 정확히 표시한다.
- 검사 링크는 기존 심장초음파·홀터·심장 표지자·경동맥초음파·ABI·검사 안내를 사용한다. 정맥초음파·CT 등 원내에서 제공하지 않는 검사는 원내 예약 가능한 검사처럼 연결하지 않는다.
- FAQ 1~3개는 기존 해설 글이나 실제 FAQ 앵커를 활용한다. 모든 질환에 협심증·판막 FAQ를 억지로 붙이지 않는다.
- 기존 증상 글의 원인 설명에도 새 질환 페이지를 연결하되, 해당 증상이 특정 질환을 확진한다는 표현을 피한다.
- 연결할 글이 없는 항목은 내부 링크 대응표에 ‘원고 없음’으로 남긴다. 링크 개수 충족을 위해 빈 페이지를 만들지 않는다. 개수 요건을 모든 글에서 엄격히 충족하려면 추가 증상·FAQ 원고 작성이 별도 범위로 필요하다.

`/diseases/cardio/` 자체의 별도 허브는 이번 기본 범위에 추가하지 않는다. 기존 `/diseases/`의 심장·혈관 필터에서 20편을 찾도록 하고, 빵부스러기는 실제 존재하는 상위 페이지만 연결한다. 추후 별도 허브를 추가하면 환자 목적과 경로 수를 다시 기록한다.

### 구현 후 실행할 검사

프로젝트 지정 환경인 Node.js 24에서 `web/` 기준으로 실행한다.

```sh
npm run content:validate
npm run build
npm run lint
npm run typecheck
npm test
npm run harness-check
npm run audit:static
npm run test:e2e
```

루트 주소와 실제 GitHub Pages의 `/yt-top-webforai` 하위 경로를 각각 빌드해 정적·브라우저 검사를 수행한다. 테스트 서버 구성은 기존 Playwright 설정을 사용한다. 변경에 필요한 테스트는 다음 실패를 검출하도록 작성한다.

- 신규 20개 영문 URL의 직접 접근·새로고침·링크 이동·canonical·사이트맵·404 처리 오류.
- 새 질환이 ‘병원안내’로 배정되거나 HTML 목록·JSON-LD 목록에서 누락되는 오류.
- 표시명·구명칭·동의어 검색 실패, 분류 순서 변경, 전체·필터·결과 개수 불일치.
- 하단 안내의 누락·중복·잘못된 적용, 응급 안내 숨김, 외국어 페이지에 한국어 문구 혼입.
- 검사 시행 가능/즉시 결과/예상 다음 날의 혼동, IMA가 현재 검사에 포함되는 오류.
- 실제 링크·본문 앵커가 없거나, 관련 FAQ·기존 URL·원 공지·사례 링크가 끊기는 오류.
- 수정 뒤 오래된 승인·검토 기록이 통과하는 오류. 신규 렌더러·데이터 변경도 승인 무효화 대상인지 확인.

94개 전체 정적 검사를 기본으로 하고, 화면은 긴 질환 글·급성 심근경색·심부전·두 백과·공통 하단·외국어 비자 안내를 PC/모바일에서 확인한다. 기존 좌측 목차, 모바일 목차·고정 연락바, 키보드, 인쇄, 출처 표기와 메타데이터를 회귀 확인한다. 성능 검사는 변경된 대표 긴 글과 백과 목록을 대상으로 한다.

공개 결과물 검사에서는 제작 설명·검토 상태·원본 DOCX·내부 대응표가 `web/out/`에 들어가지 않았는지 확인한다. 실제 배포를 진행한 뒤에만 해당 빌드의 매니페스트로 `npm run verify:live`를 실행하고, 배포 결과로 기록한다.

## 7. 최종 검토본에서 확인할 항목

계획 수립이나 일반 구현을 멈출 사유는 아니며, 완성한 문구와 적용 목록을 놓고 확인할 사항이다.

1. **검토일과 범위:** DOCX 표지·각 글은 2026-09-25, 03은 2026-09-26 통일을 요청한다. 03의 날짜를 목표로 기록하되 웹 편집본에 대한 실제 확인 없이 최종 의료 검토일·승인으로 확정하지 않는다. `updatedAt`과 의료 검토일을 구분한다.
2. **작성·의학적 검토자:** 원고에 박종설 원장 표기가 있다. 원본 표기 자체는 근거로 보존하고, 이번 병원 사실 수정·응급 문구 편집까지 검토 범위에 포함되는지 최종본과 함께 확인한다.
3. **검사 안내의 세부 범위:** 03에 명시된 가능 항목과 시간은 반영 대상으로 정한다. 문서에 없는 BNP 자체 시행 여부, 위탁 여부, 주말·공휴일 예외와 혈압계 준비·반납 안내는 필요할 때만 별도 확인한다.
4. **관련 글 개수:** 기존 콘텐츠로 연결 가능한 수를 보여주고, 부족한 증상·FAQ 원고의 추가 여부를 결정한다. 기본 계획은 없는 페이지를 만들지 않고 실제 안내에 연결하는 것이다.
5. **검색 공개:** 이번 자료 전달을 전체 새 사이트의 의료·운영 검토 완료와 production 공개 승인으로 간주하지 않는다. 기본 검토본은 기존 `noindex` 상태에서 확인한다.
