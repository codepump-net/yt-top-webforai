# AEO GEO 운영 앱 개발 작업과 검증

2026-10-16. [전체 계획](README.ko.md)과 [데이터 계약](data-contracts.ko.md)을 구현하는 작업 목록이다. 아래 항목은 모두 예정이며 실제 구현·검증이 끝난 항목만 이후 완료로 바꾼다.

## 작업 순서와 공수

개발자 1명이 기존 코드를 활용하는 경우의 추정이다. 계정 발급·공식 파일 확보·의료 검토·무료 환경에서의 관찰 기간은 포함하지 않는다. 첫 실행 검증에서 실제 CPU·계정 조건을 확인한 뒤 추정을 갱신한다.

| 묶음 | 예상 작업일 | 선행 조건 | 주요 결과 |
|---|---:|---|---|
| B0 대상과 계약 확정 | 1~2 | 없음 | 측정 설정 버전, 질문 집합, 실제 연결 목록 |
| B1 무료 환경과 인증 검증 | 2~3 | B0, Cloudflare·GitHub 접근 | staging, Access, 작은 API·D1의 실제 실행 근거 |
| B2 저장과 API 기반 | 2~3 | B1 | migration, 권한, 가져오기·조회·revision 계약 |
| B3 집계와 관측 등록 | 2~3 | B0, B2 | 기존 집계 어댑터, 관측·검토·증거 등록 |
| B4 관리 화면과 공식 파일 | 3~5 | B2, B3 | 화면 전체 흐름과 Google AI 파일 가져오기 |
| B5 자동 수집과 연결 | 2~3 | B2, 실제 연결 권한 | 기술 점검, 일반 검색 수집, 상태·재수집 |
| B6 출시 검증과 인수 | 3~5 | B1~B5의 출시 범위 | 실제 표본 대조, 보안·복구·회귀·운영 기록 |
| 합계 | **15~24** | 외부 대기 별도 | 1차 출시 범위 |

B5의 Google·Bing 연결은 권한 또는 실제 내보내기 형식 확보에 의존한다. 준비되지 않은 연결은 미연결로 남기되 해당 기능을 완료했다고 기록하지 않는다. 기술 점검 수집은 필수다. 2차 GA4·유료 AI 자동 실험은 위 공수에 포함하지 않는다.

## B0 대상과 계약 확정

- [ ] **B0-1 현재 원장 고정:** `content/pages.json`, 배포 URL·SHA, 질문 73개·대화 13개의 버전·해시를 기록한다. 과거 문서의 페이지 수를 입력으로 사용하지 않는다.
- [ ] **B0-2 도메인 규칙:** 현행 `yttop.kr`, 원 사이트 `yttop.co.kr`, 과거 GitHub Pages를 구분한다. 기존 설정을 새 버전으로 전환하고 과거 버전 원본을 보존한다.
- [ ] **B0-3 평가 질문:** 20개 핵심 질문 ID·선정 이유·브랜드 유도 여부·기대 페이지를 확정한다. 기존 73개 전체와 다중 대화의 별도 평가도 유지한다.
- [ ] **B0-4 연결 목록:** Google 속성, Bing 사이트, GA4 선택 여부, 운영자 역할과 실제 연결 가능 상태를 비공개 운영 설정에 기록한다.

완료 기준: 계약 예시가 실제 원장과 대응하고 `unknown`, 실패, 미측정, 과거 도메인 처리가 명시돼 있다. 임의 성과값은 만들지 않는다.

## B1 무료 환경과 인증 검증

- [ ] **B1-1 앱 골격:** 독립 `admin/package.json`·lockfile, React·Vite·TypeScript, Hono, Wrangler, 환경별 D1 binding을 구성한다. 현행 Node.js 24와 호환되는 버전을 확인해 잠근다.
- [ ] **B1-2 접근 제어:** 운영자 Access allowlist, 서비스 전용 정책, Worker JWT 검증, 역할 검사를 만든다. 미설정 환경은 접근을 거절한다.
- [ ] **B1-3 실제 실행 시험:** 작은 조회·등록·인증·1페이지 JSON 처리를 staging에서 측정한다. 무료 한도 아래에서 동작하는 배치 크기와 CPU 분포를 기록한다.
- [ ] **B1-4 배포 격리:** staging·production DB와 호스트를 분리하고 preview·직접 Worker 주소의 우회 접근을 확인한다. `admin/` 산출물을 `web/out/`에 복사하지 않는다.

완료 기준: 미허용 사용자는 UI·API·증거를 열지 못하고 서비스 자격은 수집 경로에만 접근한다. 실제 p95 CPU 목표 8ms와 10ms 제한 내 동작을 확인한다. 인증·입력 검사를 제거해 성능 목표를 맞추지 않는다. 넘으면 응답·배치를 줄인 뒤 유료 전환 없이 재검증한다.

## B2 저장과 API 기반

- [ ] **B2-1 DB:** 데이터 계약의 테이블·FK·unique·인덱스를 migration으로 작성한다. 새 DB와 직전 버전 DB 양쪽에 적용한다.
- [ ] **B2-2 읽기 API:** 기간·cursor·허용 필터·역할 제한, 공통 출처·갱신 메타데이터를 제공한다.
- [ ] **B2-3 쓰기 API:** 작은 배치, idempotency, 청크 manifest, 완료 전 비노출, 정정 revision을 구현한다. 잘못된 입력은 부분 등록 없이 거절한다.
- [ ] **B2-4 감사·보관:** 로그인 행위자 기반 감사 기록, 보관 만료 처리, 제한된 내보내기를 구현한다. 데이터 원문과 비밀값을 로그에 남기지 않는다.

완료 기준: 같은 파일·요청을 다시 보내도 지표가 늘지 않고, 중간 실패 후 재시도가 같은 결과로 수렴한다. 정정 전·후 값을 추적할 수 있으며 현재 값만 기본 합계에 포함한다.

## B3 집계와 관측 등록

- [ ] **B3-1 기존 코드 연결:** `measurement.mjs`, `conversation-measurement.mjs`의 순수 함수를 재사용하는 어댑터를 작성한다. 파일 읽기·보고서 출력 CLI는 Worker에 포함하지 않는다.
- [ ] **B3-2 입력 검증:** 질문 버전·원문 해시·모델·지역·수집 방식·대화 이력을 검증한다. 누락 조건은 명시적으로 분리한다.
- [ ] **B3-3 지표:** 신규·기존·합집합 인용, 병원명·사이트명 언급, 실패, 커버리지, 검토 정확도를 정의대로 구현한다.
- [ ] **B3-4 검토:** 실제 검토자의 판정과 이유·범위를 기록하고 변경 이력을 유지한다. 업로드의 검토자 이름을 로그인 검토자로 자동 인정하지 않는다.

완료 기준: 기존 의미 있는 집계 테스트가 유지되고 신규 도메인·브랜드 구분·비교 조건·중복·검토 이력의 반례를 통과한다. 합성 시험 결과가 운영 지표에 들어가지 않는다.

## B4 관리 화면과 공식 파일

- [ ] **B4-1 요약과 목록:** 출처별 카드, 페이지 추세, 관측 목록·상세, 수집 실행 목록, 연결 상태를 구현한다.
- [ ] **B4-2 파일 흐름:** 파일·속성·기간 선택, 브라우저 사전 검사, 서버 재검사, 확정 전 미리보기, 중복 안내, 취소를 구현한다.
- [ ] **B4-3 Google AI parser:** 실제 공식 파일로 열·기간·차원·필터를 확인한다. property/page 등 합계가 다른 표를 분리하고 모호한 0을 보존한다. 실제 파일을 확보하기 전에는 합성 계약 검사까지만 완료 처리한다.
- [ ] **B4-4 사용성:** 빈 상태·미연결·부분 실패·오래된 데이터, 필터 초기화, 키보드·모바일·표 접근성, 안전한 원문·링크 렌더링을 검증한다.

완료 기준: 사용자가 숫자에서 원본 증거로 이동할 수 있고 출처·기간·분모·갱신 시각을 함께 이해할 수 있다. 다운로드한 공식 보고서의 표본 수치를 수동 대조한 기록이 있다. 파일이 없어서 못 한 대조는 미완료로 남긴다.

## B5 자동 수집과 연결

- [ ] **B5-1 기술 수집:** 자사 URL allowlist, 4개 이하 동시 요청, manifest·SHA 연결, 결과 정규화와 서비스 인증 업로드를 구현한다.
- [ ] **B5-2 일반 검색:** 공식 읽기 권한, 날짜별 총계·페이지표, 최근 7일 재조회, 잠정·상위 행 제한, 토큰 만료를 구현한다.
- [ ] **B5-3 선택 연결:** 준비된 Google URL Inspection 표본과 Bing 파일 parser를 추가한다. GA4는 2차로 남긴다.
- [ ] **B5-4 실행 관리:** 일별·수동 workflow, source별 잠금, 재시도·timeout·체크포인트, 요청 대기열, 로그 정리, 사용량 기록을 구현한다.

완료 기준: 실제 기술 수집 3회 이상에서 중복·오류·재수집 동작을 검증한다. API 연결이 준비됐다면 실제 기간 표본을 서비스 화면과 대조한다. workflow가 실행됐다는 사실만으로 데이터 수집 성공을 표시하지 않는다.

## B6 출시 검증과 인수

- [ ] **B6-1 권한·계약 시험:** 아래 검사표를 수행하고 실패를 해결한다.
- [ ] **B6-2 복구:** 백업을 별도 staging DB에 복원하고 건수·현재 revision·대표 지표를 대조한다.
- [ ] **B6-3 환자 사이트 회귀:** 변경 범위에 맞는 기존 콘텐츠·정적 export·테스트와 배포 보호 조건을 확인한다.
- [ ] **B6-4 운영 시작:** production 배포 SHA·DB migration 버전·Access 설정 확인·계정 연결 상태·사용량·첫 실제 관측을 기록하고 담당자에게 실행 절차를 전달한다.

완료 기준: [출시 체크리스트](operations.ko.md)의 필수 조건이 모두 통과한다. 운영 원본은 비공개로 남기고 저장소에는 비식별 검증 요약만 기록한다.

## 실행할 검사와 증거

앱 개발 시 `admin/`에 `lint`, `typecheck`, `test:unit`, `test:integration`, `test:e2e`, `build` 스크립트를 만든다. 명령 이름은 계획이며 아직 실행 가능한 스크립트가 아니다. Worker/D1 로컬 검사는 실제 runtime 호환 환경을 사용하고 Access·무료 CPU·실제 계정 대조는 staging에서 수행한다. mock 통과를 실환경 검증으로 대체하지 않는다.

공유 측정 함수나 원장이 바뀌면 `web/`의 관련 단위 검사와 `npm run content:validate`를 수행한다. 환자용 빌드·렌더러·workflow가 바뀌면 현행 review/production 콘텐츠·export·브라우저 검사와 배포 SHA 검증을 유지한다. 유효한 공개 확인 없이 production gate를 통과시키기 위해 승인 기록을 만들거나 바꾸지 않는다.

문서만 변경한 작업은 문서 링크·형식·범위 검사로 검증한다. 실제 구현·원고를 바꾸지 않았는데 앱 전체 테스트를 수행한 것처럼 기록하지 않는다.

합격 증거에는 검사 시각, 코드 SHA, 대상 환경, 스키마 버전, 검사항목, 결과, 남은 제약을 넣는다. 샘플 수와 실제 연결 유무를 명시한다. 운영 중 사용하는 별도 비공개 기록의 위치만 내부 운영자에게 전달하고, 공개 문서에는 자격 증명·계정 식별자·원본 답변을 넣지 않는다.
