# 원장님 제공 원고와 현재 사이트의 종합 비교 검토

> 후속 작업: [2026-09-25 개편 구현 및 검증 결과](implementation.ko.md). 아래 문서는 구현 전 종합 검토 기록입니다.
검토 기준일: 2026-09-25. 내부 기획·개발 문서이며 병원 웹사이트에 게시하지 않는다.

대상: 원장님 제공 문서(로컬 `plan/new_20260925.md`), [검토 당시 45개 경로의 콘텐츠 원장](../../content/pages.json), [페이지 목적](../../content/page-intents.json), 병원·의료진 데이터, 렌더러·구조화 데이터·배포 검증, 실제 배포 HTML. 원고별 판단은 [46편 반영 대응표](article-mapping.ko.md), HTTP 확인과 원고 위치는 [검토 증거](evidence.json)에 기록했다.

## 1. 권고하는 개편 수준

**기존 기술 기반을 유지하면서 핵심 페이지의 내용을 대폭 보강하고, 빠진 진료·환자 질문을 선별 확장하는 콘텐츠 개편이 필요하다.** 원장님 문서는 이 개편의 주요 원천 자료로 적합하다. 46편을 그대로 별도 URL로 추가하는 방식은 중복과 관리 부담이 크다.

현재 사이트는 검사·방문 안내의 구조와 안전한 표현을 갖췄다. 다만 여러 페이지가 “가능한 항목을 문의하세요”, “개별 안내를 확인하세요”에서 답변을 끝내 실제 병원의 역량과 진료 과정을 충분히 설명하지 못한다. 원장님 자료는 그동안 비어 있던 **구체적인 병원 사실, 임상적 판단 이유, 실제 가능한 처치와 의뢰 범위**를 제공한다.

권고 범위는 다음과 같다. 숫자는 아래 환자 목적에 따른 설계안의 결과이며 SEO 목표치가 아니다.

| 단계 | 개편 범위 | 완료 후 예상 경로 수 |
|---|---|---:|
| 1차 | 기존 소개·의료진·진료·검사·검진·방문 페이지 보강, 핵심 한국어 신규 12개 | 57 |
| 2차 | 판막·협심증·만성질환 등 심화 한국어 신규 9개 | 66 |
| 다국어 | 기존 한국어 비자 안내에 대응하는 외국어 5개 | 71 |

현재 45개에 검색·404가 포함되어 있다. 위 예상치도 같은 기준이며 모두 승인·공개할 경우 색인 후보는 69개다. 실제 편집 과정에서 한 페이지로 충분하면 통합한다. 과거 폐기된 76개 계획을 복원하는 제안이 아니다.

## 2. 원장님 자료의 내용과 의도

문서는 약 10.1만 자, 번호가 붙은 원고 46편이다. 상단에 박종설 원장 작성·검토, 2026-09-24 최종 검토가 명시되어 있다. 본문은 6개 원고 묶음이며, 뒤에 공통 안내·4개월 게시 순서·34개 참고자료 항목이 붙는다. 참고자료 항목 수는 서로 다른 검증 완료 출처 수를 뜻하지 않는다.

| 원고 | 주요 내용 | 사이트에 요구하는 변화 |
|---|---|---|
| 1–5 | 병원·의료진, 진료 범위, 장비, 응급 전원 | 어떤 환자를 어떤 근거로 평가하고 어디까지 진료하는 병원인지 설명 |
| 6–13 | 심장검사 순서, 국가·암·채용·비자 검진, 초음파·내시경 준비 | 환자가 방문 전 실제로 준비하고 검사 과정을 예상할 수 있는 안내 |
| 14–21 | 흉통·부정맥·판막·협심증, 암 지지진료·발열, 급성 복통·감염 | 증상별 판단과 의원 진료·상급병원 의뢰의 연결 |
| 22–31 | 약 복용, 담석, 가족력, 백신, 간수치, 용종, 갑상선암, 비만약 | 진료 전후 환자가 계속 묻는 질문에 대한 설명 |
| 32–41 | 장정결제, 보호자, 복약, 시술 후 관리, 서류, 6개 언어 안내 | 준비 실패·재방문·서류 발급 지연을 줄이는 실무 정보 |
| 42–46 | 항암 중 증상별 대처, 독감 예방·진료, 코로나19, 성인 예방접종 | 새로 강조하는 진료 분야와 계절·고위험군 정보 확장 |

원장님의 의도는 문서에서 다음과 같이 읽힌다. 이는 문서에 근거한 편집적 해석이다.

1. **정확한 진단과 환자 안전**을 병원의 핵심 원칙으로 보이게 한다.
2. 심장·소화기·호흡기 증상을 함께 판단하는 내과 전문성을 설명한다.
3. 암환자에게 제공하는 지역 지지진료의 역할을 구체화한다.
4. “무슨 검사를 하나요?” 다음에 “왜 하나요?”, “무엇을 준비하나요?”, “여기서 가능한가요?”까지 답한다.
5. 검진·서류·예방접종처럼 실제 방문으로 이어지는 정보를 충분히 제공한다.

이미 답변을 먼저 제시하고 검사 한계·응급 신호·약물상호작용을 설명하는 점은 강점이다. 문서 전체를 단순 홍보 원고로 취급하거나 안전 안내만 남겨 다시 추상화하면 요청의 핵심을 잃는다.

## 3. 현재 구현 상태와 차이

### 현재 상태를 판단한 기준

과거 감사 보고서의 검토 모드 설명보다 [최신 production 공개 기록](../production-release-2026-09-11/README.ko.md)과 실제 응답을 우선했다. 2026-09-25에 45개 경로를 직접 요청하여 HTML·JSON-LD를 확인했다.

- 전체 경로 45개, 색인 허용 43개, 검색·404의 noindex 2개.
- 사이트맵 43개 URL. 27개 페이지에 구조화된 문답 82개.
- 건강정보 독립 글은 4개. 의료진 프로필 2개와 사례 원문 연결 25개 유지.
- MedicalClinic·Person·Service·MedicalTest 계열·Article·FAQPage 등은 이미 구현되어 있다. 29종 집계와 Lighthouse 결과는 9월 11일 검증 이력이다.
- 이번 확인은 HTTP와 정적 HTML 검사다. 브라우저 화면·Lighthouse 재측정, 검색엔진 색인 확인, 실제 AI 인용 실험은 수행하지 않았다.
- `/404.html` 파일은 HTTP 200이었다. 이것으로 임의의 잘못된 URL도 200이라고 판단하지 않는다.
- 기존 `yttop.co.kr`은 이번 요청에서 403이었다. 기존 사이트 전체의 현재 내용까지 대조했다고 주장하지 않는다.

**따라서 “아직 noindex라 노출되지 않는다” 또는 “FAQ·구조화 데이터를 처음 만들어야 한다”는 진단은 현재 상태와 맞지 않는다.** 검색 공개가 허용된 것과 실제 색인·AI 인용이 발생한 것은 별개다.

현재 [병원 데이터](../../content/clinic.json)의 `breakUnconfirmed: true` 때문에 토요일 시간은 구조화 데이터에서 제외된다. 이번 토요일 운영정보 보완은 환자 화면뿐 아니라 AI가 읽는 병원 시간 정보도 구체화할 수 있다.

새 자료에 언급이 없다는 이유로 박라영 원장, HRV, 기존 ABI 안내, 기숙사 검진, 비용·개인정보·사례·공지 기능을 삭제해서는 안 된다. 추가 자료의 범위와 기존 정보의 유효성은 별개다.

## 4. 게시 전에 정리해야 할 내용

아래 항목은 원고 전체가 부정확하다는 뜻이 아니다. 병원에서 제공한 운영 사실은 새 근거로 활용하되, 원고 안의 충돌과 의학·제도상의 조건을 해결하자는 판단이다. 이번 검토는 46편 전체의 개별 의학 주장과 모든 참고문헌을 완전 검증한 의료 감수가 아니다.

| 항목 | 발견한 문제 또는 확인 범위 | 반영 기준 |
|---|---|---|
| 검진 접수시간 | 원고 8·9의 08:30–15:30, 10의 08:30–17:00에 요일 구분이 없다. 토요일 진료 종료 13:30·평일 점심과 함께 읽으면 혼동 가능 | 평일/토요일, 접수/검사, 점심 제외 여부를 분리하여 확정 |
| 원장 경력·자격 | 기존 현직→새 자료 전직 변경, 임상교수 기관명 차이, 새 자격 제시 | 새 문서를 변경 근거로 기록. 자격증 정식 명칭과 학회별 인증 범위를 맞춤. 순환기 분과전문의 자격을 추정하지 않음 |
| 주차·예약 | 지하주차 가능은 제시되지만 무료시간은 없다. 전화 재예약 제한의 적용·예외 범위도 상세하지 않음 | 지하주차 사실 반영, 무료·확정 예약·항상 당일진료 약속은 추가하지 않음. 취소 규정은 예약 문맥에 배치 |
| 검사 소요시간 | Troponin I 약 20분과 검사 전체 소요시간은 다르다. 서류 1–2시간도 정상 판독·서식 충족 조건이 있음 | 무엇의 소요시간인지 밝히고 재검·위탁·주말 예외를 같은 답변에 포함 |
| 장정결제 | 13·32의 물 500mL+1L, 13·33의 플렌뷰 추가 음료 약 480mL와 용기 표시선 설명 | 병원 실제 제품·국내 허가사항·배부 안내문 대조. 제품명·용해량·추가 수분·검사시각·금식 종료를 하나의 표로 관리 |
| 플렌뷰 출처 | 참고문헌의 United Digestive 자료는 미국 의료기관 안내문이다. 원고 33의 “공식 복용설명서”와 동일하게 취급할 수 없음 | 국내 제품 자료와 구분해 출처명 교정. 한국파마에 2026-06-19 허가변경 공지가 존재함을 확인했지만 첨부의 변경 내용은 미검증 |

### 기존 페이지와의 역할 구분

- 검사 페이지: 검사 목적·원내 시행·예약·결과·한계.
- 준비 글: 이미 예약한 사람이 실제로 따라야 하는 준비와 연락 기준.
- 질환·증상 글: 가능한 원인, 진료 판단, 병원에서 하는 일, 의뢰 기준.
- 병원 서비스 페이지: 제공 가능한 진료와 준비 자료, 방문 경로.

예를 들어 원고 18은 기존 암환자 서비스 페이지의 중심 내용으로, 42는 증상 안내로, 19는 발열 행동 안내로 사용한다. 세 곳에 긴 원고를 반복하지 않고 핵심 요약과 문맥에 맞는 연결을 둔다. 보호자 동행(34)은 위·대장내시경과 준비 페이지의 공통 기준으로 우선 반영한다.

### 6개 언어 안내

한국어는 기존 `/checkups/visa/`를 기준으로 결핵 서류까지 보강한다. 영어·중국어 간체·태국어·러시아어·네팔어는 각각 `/en/checkups/visa/`, `/zh-hans/checkups/visa/`, `/th/checkups/visa/`, `/ru/checkups/visa/`, `/ne/checkups/visa/`를 제안한다. 원고 41은 한 편 안에 여섯 언어가 있는 자료이며 여섯 개의 한국어 글이 아니다.

각 번역에는 한국어 기준판과 같은 검사·준비물·발급조건이 있어야 한다. 제목·메타데이터·`lang`·`inLanguage`·자기 canonical과 상호 `hreflang`을 맞춘다. 언어별 페이지를 한국어 URL로 모두 canonical 처리하지 않는다. 현재 코드가 한국어로 고정되어 있어 본문 번역만 추가해서는 완료되지 않는다. 번역 제공이 병원의 해당 언어 상담 가능을 뜻하지 않으므로 `availableLanguage`를 자동 확장하지 않는다. [Google 다국어 페이지 안내](https://developers.google.com/search/docs/specialty/international/localized-versions).

## 6. AEO·GEO 관점의 실행 전략

### 목표를 측정 가능한 행동으로 바꾸기

사업 목표는 **환자의 관련 질문과 후속 대화에서 병원의 정확한 정보가 발견·인용·언급되고, 적절한 방문으로 이어질 기회를 늘리는 것**이다. 모든 의료 질문에서 병원명이 반복되게 하거나 노출 최대치를 보장하는 목표는 사이트만으로 통제할 수 없다. 특히 응급 질문에서는 병원 예약보다 올바른 긴급 행동을 안내하는 것이 성공이다.

이 검토에서 AEO는 질문에 충분히 답하는 정보 설계, GEO는 생성형 검색이 그 정보를 발견·이해·인용할 수 있는 공개·신뢰·연결 구조로 사용한다. 공식 순위 점수나 인증을 뜻하지 않는다.

Google의 최신 가이드는 직접 경험·전문성이 있는 고유한 콘텐츠, 읽기 좋은 구성, 기존 SEO를 강조한다. `llms.txt`, 인위적인 짧은 조각 만들기, 특수 스키마를 별도 성공 조건으로 제시하지 않으며, 질문 변형마다 페이지를 양산하는 접근도 권장하지 않는다. **따라서 46편의 반복을 줄이고 실제 병원 진료 정보를 충실히 담는 방향이 타당하다.** [Google 생성형 AI 검색 최적화 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

### 답변의 내용과 연결

각 주요 질문에는 결론, 적용 조건, 영통탑내과의 실제 역할, 다음 행동을 자연스럽게 이어 쓴다. 글자 수나 병원명 반복 횟수에 대한 최적화 규칙을 만들 필요는 없다. 병원명은 제공 기관을 식별할 때 사용한다.

예시 초안 — 원고 3·6·7·15에 근거하며 최종 게시문은 별도 편집 대상:

> 영통탑내과에서는 홀터검사를 주로 72시간 시행합니다. 검사 중 증상이 나타난 시각과 활동을 기록하면 심전도와 비교하는 데 도움이 됩니다. 검사기간에 증상이 없었다면 부정맥을 완전히 배제하기 어려워 추가 평가가 필요할 수 있습니다. 착용·반납 일정은 전화 예약 시 안내받으세요.

일반적인 검사 정의만 제공하는 답변보다 실제 병원에서의 검사·준비·후속 행동을 함께 이해할 수 있다. 이것이 AI 인용률을 얼마나 올리는지는 관측으로 확인해야 한다.

| 대화의 흐름 | 연결할 콘텐츠 | 기대하는 정확한 정보 |
|---|---|---|
| 심전도 정상인데 두근거림 → 어떤 검사 → 망포역에서 가능한 곳 → 준비·예약 | 검사 차이 → 두근거림 → 홀터 → 방문 | 검사 차이, 주로 72시간, 기록·전화예약, 응급 예외 |
| 항암 중 식사를 못함 → 가까운 내과 역할 → 준비 자료 | 증상 대처 → 암 지지진료 → 방문 | 탈수·위험 평가, 기존 치료팀 연계, 실제 처치 범위 |
| 항암 중 38℃ 발열 → 어디로 가야 하나 | 발열 행동 안내 | 담당 치료팀·응급실 연락. 의원 방문 유도가 성과 기준이 아님 |
| 대장내시경 예약 → 받은 약 → 물·식사 → 검사 후 운동 | 준비 안내 → 제품별 복용 → 시술 후 관리 | 제품·예약시간에 맞는 안내, 임의 복약 중단 방지 |
| 수원 E-2 검진 → 준비물 → 결핵서류 시간 → 위치 | 비자 → 결핵 안내 → 방문/언어판 | 제출처 조건, 발급 예상기간과 예외, 609호 |
| 고령자 코로나 증상 → 치료 가능기간 → 복용약·검사 | 코로나19 → 진료·검사 → 방문 | 조기 진료, 상호작용, 병원 검사 원칙과 의뢰 기준 |

이 연결은 환자 탐색을 돕는 설계다. 특정 AI가 링크 순서대로 대화하거나 모든 페이지를 읽는다고 가정하지 않는다.

### 공개·발견·병원 식별

1. 기존 정적 HTML·고유 URL·본문과 일치하는 구조화 데이터·내부 링크를 유지한다. 새 사실을 본문·메타 설명·FAQ·JSON-LD에 함께 반영한다.
2. 병원명·전화·주소·의료진·시간을 기존 사이트 및 실제 관리 중인 지도/사업자 프로필과 대조한다. 신규 사이트로의 공식 연결은 환자가 진료·준비 안내를 찾는 문맥에서 제공한다. 새 위치나 별도 병원으로 등록하지 않는다.
3. `https://yttop.co.kr/#clinic` 병원 ID와 두 사이트의 병행 운영을 유지한다. 공지·사례 원문을 복제하거나 기존 사이트 전체를 새 사이트로 canonical/301 처리하지 않는다.
4. 현 GitHub Pages 프로젝트 하위의 `/yt-top-webforai/robots.txt`는 HTTP 200이지만 호스트 루트 `/robots.txt`는 404다. 하위 파일을 호스트 전체에 적용되는 로봇 제어로 보고하면 안 된다. 루트 파일 부재가 곧 수집 차단을 뜻하는 것도 아니다. 병원 소유 도메인/서브도메인은 장기 운영과 루트 제어를 위한 선택지이며 순위 상승을 보장하지 않는다. [Google robots.txt 작성 규칙](https://developers.google.com/search/docs/crawling-indexing/robots/create-robots-txt).
5. ChatGPT 검색을 위한 `OAI-SearchBot` 접근과 방화벽 차단 여부를 확인한다. 학습용 `GPTBot`은 별도 제어이며, 학습 허용을 검색 노출 조건으로 보지 않는다. 이번 일반 HTTP 성공이 실제 봇 IP의 접근 성공을 증명하지는 않는다. [OpenAI 크롤러 공식 문서](https://developers.openai.com/api/docs/bots).

### 2026년 기준으로 갱신해야 하는 검색 운영 항목

- Google은 2026-05-07부터 FAQ 리치결과를 종료했다고 명시했다. 기존 FAQPage는 화면 문답을 설명하는 데이터로 유지할 수 있으나, FAQ 리치결과 확보를 이번 개편의 성과 목표로 잡지 않는다. [Google 변경 기록](https://developers.google.com/search/updates#may-2026).
- 현재 공식 안내에는 Search Console의 **Search generative AI** 포함/제외 설정이 있다. 새 사이트와 부모 속성에서 실제 적용값을 확인할 운영 항목으로 추가한다. 기본 포함이라는 공식 설명만으로 이 사이트의 계정 상태를 확인했다고 보고하지 않는다. [Search generative AI control](https://support.google.com/webmasters/answer/16908024).
- 공식 문서에 **Generative AI performance report**도 안내되어 있다. 노출이 충분하지 않으면 보고서가 안 보일 수 있고, Google 검색 AI 기능의 노출 지표이므로 ChatGPT·다른 서비스 전체의 성과와 합치지 않는다. 과거 “일반 Web 보고서에서만 확인”하는 설명은 갱신할 필요가 있다. [생성형 AI 성과 보고서](https://support.google.com/webmasters/answer/16984139).

## 8. 순서와 완료 기준

### 권고 순서

1. **운영·병원 사실 정리:** 주소·시간·경력·원내 검사·암 처치 범위를 새 자료와 연결하고, 위 충돌 목록만 좁혀 정리한다.
2. **기존 핵심 페이지와 1차 신규 원고:** 홈에서 심장·암 지지진료·호흡기·검진·예방접종까지 찾아갈 수 있게 한다. 장정결제·코로나·검진 제도는 해당 근거 확인과 함께 진행한다.
3. **심화 9개와 외국어 5개:** 단순 반복이 아닌 설명을 완성하고 원문·번역의 변경을 동기화한다.
4. **공개본 검증과 배포:** 기존 production 검증을 유지하고 최종 결과물과 배포 내용을 대조한다.
5. **발견·인용 관측:** 공개 전 기준값과 공개 후 같은 조건의 반복 관측을 비교한다.

원고의 4개월 게시 순서는 블로그 운영안으로 활용할 수 있다. 병원 사실 정정이나 필수 검사 준비 안내를 그 순서 때문에 몇 달씩 늦출 필요는 없다.

### 콘텐츠 완료 기준

- 원고 46편 모두 반영 위치·통합 이유·보류 이유가 추적된다.
- 병원 운영 사실은 페이지 간 상충하지 않고, 제공·미제공·의뢰 범위가 구분된다.
- 환자가 질문의 핵심 답과 준비 행동을 이해한다. 확인된 정보까지 전화문의 문구로 대신하지 않는다.
- 응급 증상과 약물·금식 조건은 요약·FAQ에서도 유지된다. 위험 정보가 접힌 FAQ 안에만 있지 않는다.
- 검토자·자격·출처·시행연도는 근거에 맞고 번역판도 같은 의미를 전달한다.
- 새 자료에 없는 비용·결과 보장·협약기관·추가 의료진 자격을 만들지 않는다.

### 개발·배포 완료 기준

변경 후 `content:validate`, lint·타입 검사, 관련 단위 검사, 정적 빌드·`audit:static`, 브라우저 회귀 검사를 수행한다. 루트·프로젝트 경로, 모바일 메뉴·본문 표·인쇄, 링크·앵커·검색, HTML과 JSON-LD 일치, 다국어의 실제 lang/canonical/hreflang, 내부 문서 미노출을 확인한다. production 검증과 같은 실행의 매니페스트를 이용한 `verify:live`를 유지한다. 기존 성능·접근성 수정도 회귀 검사한다.

**이번 작업에서는 공개 원고·애플리케이션을 변경하지 않았으므로 빌드·테스트를 새로 실행하지 않았다.** 대신 원고 번호·대응 경로·로컬 문서 링크·수량을 검사하고 실제 배포 45개 경로의 HTTP·색인 지시·canonical·문답을 확인했다. 현재 로컬에는 `node_modules`와 `web/out`이 없다. 기존 빌드 통과 기록과 이번 검토 결과를 구분한다.

## 9. 실제 AI 대화 노출을 측정하는 방법

기존 측정기는 32개 질문, 신규/기존 사이트 인용률, 병원명 언급률, 사람의 정확성 평가, 오류 응답 제외를 지원한다. 이 기반을 확장한다. 코드가 존재한다는 것만으로 기준 인용률이 측정된 것은 아니다.

| 평가 묶음 | 예시 | 목적 |
|---|---|---|
| 브랜드 질문 | 영통탑내과 홀터검사는 얼마나 하나요? | 명시된 병원 정보의 정확한 회수 |
| 지역·비브랜드 질문 | 망포역 근처에서 홀터검사를 상담할 수 있는 내과 | 병원명을 먼저 주지 않은 상태의 발견 |
| 의학적 질문 | 심전도가 정상인데 두근거림이 계속돼요 | 유용한 설명의 출처로 인용되는지 확인 |
| 후속 대화 | 검사 차이 → 지역 → 해당 병원 검사기간 → 준비 | 여러 턴에서 병원 정보가 정확하게 이어지는지 확인 |
| 방문 실행 | 비자검진 준비물·발급일·주차·토요일 시간 | 상담·방문을 준비하는 정보 정확성 |
| 응급 예외 | 항암 중 발열, 지속 흉통·호흡곤란 | 위험한 의원 방문 유도 없이 적절히 안내하는지 확인 |

편집 평가용으로 3–4턴 시나리오 10개를 먼저 설계하고, 같은 질문 세트를 서로 다른 새 세션에서 반복한다. 브랜드를 넣는 질문과 넣지 않는 질문을 나누고, 첫 턴에 병원명을 알려준 결과를 자연 발견으로 집계하지 않는다. 이 숫자는 검색빈도 조사 결과가 아니다.

필수 기록은 엔진·모델·검색 모드·지역·언어·시각·질문 세트 버전·대화 ID·턴 번호·앞선 질문/답변·인용 URL이다. 현 측정기는 단일 답변의 `queryId/runId` 중심이므로 대화 시퀀스와 분모를 추가해야 한다.

- **발견률:** 병원명을 제시하지 않은 유효 대화 중 병원이 적절히 등장한 비율.
- **인용률:** 신규 사이트, 기존 사이트, 두 사이트 중 하나를 인용한 비율을 각각 집계.
- **후속 유지율:** 병원이 처음 등장한 뒤 관련 후속 답변에서 정확한 병원 정보가 이어진 비율. 관련 없는 턴은 제외.
- **사실 정확성:** 주소·시간·시행 검사·미시행 항목·처치·발급조건을 사람 기준표와 대조.
- **환자 행동:** 전화·지도 클릭 등 방문 준비 행동을 별도로 측정. 클릭을 실제 내원으로 간주하지 않음.
- **검색 관측:** Search Console의 실제 색인 상태와 생성형 AI 노출 보고서를 확인. 다른 AI 서비스의 대화 표본과 구분.

개편 전과 공개 후 2·4·8주 등 동일한 간격의 표본 비교를 권한다. 모델·계절·질문 변화도 기록하고, 증가를 개편의 단독 인과효과로 주장하지 않는다. 고정 인용률 목표치는 실제 기준값을 확보한 뒤 정한다. 환자 대화·질병 정보는 실험용으로 수집하지 않고 비식별 가상 시나리오를 사용한다.

## 최종 판단

원장님 자료는 현재 사이트가 부족하게 전달하던 실제 진료의 내용과 판단 기준을 채우는 데 가치가 크다. **기존 페이지의 직접적인 답변을 보강하고, 암환자·호흡기·예방접종·검사 준비·서류 안내를 확장하는 수준의 콘텐츠 개편**을 권고한다. 각 원고를 환자의 질문과 행동에 맞는 위치로 재구성하고 실제 인용·정확성을 관측하는 것이 이번 목적에 가장 잘 맞는다.
