# 영통탑내과·더건강한365·올림픽파크365 SEO / AEO / GEO 비교

평가일: 2026-09-11 KST. 내부 검토 문서이며 환자용 웹사이트에 게시하지 않는다. 실제 배포 URL에 대한 HTTP·브라우저·Lighthouse 관찰을 기준으로 작성했다.

이 문서는 검색 공개 전의 비교 기록이다. 이후 사용자가 의료·운영 확인 완료와 공개를 승인해 production 배포를 진행했다. 현재 상태와 후속 검증은 [검색 공개 및 구조화 데이터 릴리스 기록](../production-release-2026-09-11/README.ko.md)을 참조한다. 아래의 noindex·빈 사이트맵·SEO 66은 변경 전 측정값으로 보존한다.

**현재 검색에 공개할 기술적 조건은 두 공개 블로그가 앞선다. 영통탑은 검사·방문 안내 구조와 모바일 성능이 강하지만, 배포된 44개 정상 페이지 모두 `noindex`여서 검색 공개 단계에 도달하지 않았다.** 두 블로그의 질문형 원고·저자 연결·논문 인용은 좋은 비교 사례다. 다만 주소·진료시간 불일치와 큰 이미지 전송량까지 확인돼, 어느 사이트도 모든 항목에서 우수하다고 평가할 수 없다.

이 문서의 AEO는 환자의 질문에 답하는 정보 구성, GEO는 생성형 검색에서 출처로 활용하기 위한 접근성·정보의 명확성·근거 추적 가능성을 뜻한다. 검색엔진이 제공하는 공식 점수가 아니다. 항목 간 가중치가 합의되지 않았고 실제 노출 자료도 없으므로 임의의 100점 종합점수나 인용 확률은 계산하지 않았다.

**같은 환경에서 측정한 모바일 성능**

공개된 세 홈페이지를 같은 Windows Edge 환경에서 Lighthouse 13.4.1 기본 모바일 시뮬레이션으로 차례대로 1회씩 검사했다. 데모 성능은 별도 순위를 매기지 않았다. 이 측정은 이전 로컬 성능 보고서의 수치를 옮겨 적은 것이 아니다.

| 측정값 | 영통탑 | 더건강365 공개 | 올림픽파크365 공개 |
|---|---:|---:|---:|
| Lighthouse 성능 | **100** | 71 | 62 |
| 접근성 자동 검사 | **100** | 88 | 88 |
| Lighthouse SEO | 66 | 100 | 100 |
| LCP: 주요 콘텐츠 표시 | **1.72초** | 11.78초 | 9.72초 |
| CLS: 레이아웃 이동 | 0 | 0.0012 | 0.0006 |
| TBT: 긴 JS 작업에 의한 차단 | 16ms | 7ms | 17ms |
| 측정 중 총 네트워크 전송량 | **0.208MB** | 23.724MB | 19.349MB |

전송량은 1MB=1,000,000바이트이며 HTML 크기만을 뜻하지 않는다. 두 블로그는 이번 측정에서 메인 스레드 차단보다 이미지 전송량이 큰 문제로 관찰됐다. 더건강365의 의료진 이미지 한 장은 약 3.82MB, 올림픽파크365의 고압산소 분야 이미지는 약 4.68MB였다. 화면 크기에 맞춘 이미지 변환·반응형 이미지·화면 밖 이미지의 로딩 시점을 우선 검토할 만하다. [측정 증거](lighthouse-evidence.json).

영통탑의 Lighthouse SEO 66은 `noindex`에 따른 `is-crawlable` 실패로 설명된다. 나머지 두 사이트의 SEO 100도 주소 일치, 출처 정확성, 실제 노출 성과까지 100점이라는 뜻은 아니다. 접근성 검사에서 두 블로그 모두 대비, 터치 영역, `aria-hidden` 안의 포커스 가능한 요소가 지적됐다. 영통탑의 접근성 100 역시 수동 접근성 검사 전체의 합격을 보장하지 않는다.

1회 실험이므로 네트워크·서버·이미지 캐시와 화면 내용에 따른 변동이 있다. CrUX의 실제 사용자 LCP·INP·CLS와 구분해야 한다. TBT는 INP가 아니다. 세 사이트 모두 이번 작은 모바일 화면의 홈에서는 가로 넘침과 깨진 이미지가 관찰되지 않았다. [브라우저 기록](browser-evidence.json).

**영통탑: 잘된 부분과 남은 일**

현재 가장 큰 노출 제약은 메타태그 수가 아니라 의도적인 검색 제외 상태다. [사이트맵](https://codepump-net.github.io/yt-top-webforai/sitemap.xml)은 비어 있고 정상 경로 전체가 noindex다. 저장소의 환자 콘텐츠 기준에 따르면 의료·운영 승인 근거가 없는 동안 검토 모드를 유지하는 설계다. 이를 실수로 단정하거나 평가 작업 중 제거하지 않았다. Google 생성형 검색의 출처 자격에는 색인과 스니펫 노출 가능성이 필요하므로, 지금 상태를 이미 SEO/GEO 성과가 좋은 사이트로 보고할 수 없다. [Google AI 검색 기술 요건](https://developers.google.com/search/docs/appearance/ai-features#technical-requirements).

HTML 제목·설명·canonical·H1은 44개 모두 갖춰져 있고 제목·설명은 각각 중복이 없었다. 의료정보 25개에는 MedicalWebPage, 의료진 프로필 2개에는 ProfilePage·Person이 있다. 병원 식별자는 기존 `yttop.co.kr/#clinic`, 새 사이트와 각 페이지 식별자는 새 URL을 사용한다. 같은 병원이라는 사실을 연결하면서 기존 공지·사례 채널을 유지하는 현재 목적에 맞는다. 새 안내 페이지의 자기 canonical을 일괄 원 사이트로 바꾸거나 기존 사이트를 전부 리다이렉트할 이유는 이번 조사에서 확인되지 않았다.

[대장내시경 준비](https://codepump-net.github.io/yt-top-webforai/health/colonoscopy-preparation-questions/)는 음식·정결제·물·예약시각을 구분하고, [두근거림 검사 후 안내](https://codepump-net.github.io/yt-top-webforai/health/palpitations-test-followup/)는 다음 상담에 가져갈 기록과 긴급 증상을 안내한다. 단순 키워드 목록보다 환자의 행동을 돕는 내용이다. 다만 개별 병원의 확인된 예약·검사·결과 안내가 더 보강되면 ‘문의해야 한다’에서 끝나는 질문을 줄일 수 있다. 약 중단·금식 시각 등을 검색 노출을 위해 임의로 확정해서는 안 된다.

출처는 확보돼 있지만 공개 의료정보의 author·reviewedBy·lastReviewed는 이번 배포본에서 관찰되지 않았다. 실제 기록 없이 이를 채우지 않은 것은 사실성 측면에서 적절하다. 실제 의료진 검토가 이뤄진 뒤 그 사람과 검토일을 본문과 데이터에 일치시켜 추가하면 책임 주체의 추적 가능성이 좋아진다. 별도의 공개 검수 정책·개발 상태 페이지를 만들 필요는 없다.

본문에는 토요일 시간이 있으나 구조화 데이터에는 평일 시간만 있다. `content/clinic.json`에서 토요일 점심 적용이 미확정으로 기록돼 있어 의도적으로 보류한 부분이다. 운영 사실 확인 후 일치시킬 사항이며, 임의로 토요일 시간을 추정해서 추가할 항목은 아니다.

호스트 루트 `https://codepump-net.github.io/robots.txt`는 404이고 프로젝트 하위 `/yt-top-webforai/robots.txt`만 200이다. robots 규칙은 호스트 루트에 있어야 적용된다. 404 자체가 수집을 막는 것은 아니지만 프로젝트 하위 파일을 유효한 호스트 규칙으로 믿어서는 안 된다. 공개 전환 시 루트 제어 가능 범위와 사이트맵 직접 제출 경로를 확인하면 된다. 커스텀 도메인 이전이 필수라는 뜻은 아니다. [Google robots 파일 위치 안내](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt).

**더건강365 공개 블로그: 좋은 답변 구조와 주소·이미지 문제**

표본 7개 글 모두 Article의 citation·author와 MedicalWebPage의 reviewedBy·lastReviewed를 갖고, 실제 본문에는 실명 저자와 프로필 연결이 있다. [일요일 복통 글](https://blog.thegungang365.com/sunday-abdominal-pain-sinjeong-dong)처럼 상황 질문, 짧은 답변, 근거와 한계, 위험신호, 병원의 진료 방식으로 이어지는 구성이 좋다. 단, 표시는 실제 집필·검토 행위를 독립적으로 증명하지 않는다.

[홈페이지](https://blog.thegungang365.com/)의 위치 FAQ는 **신원로 280**, 푸터와 MedicalClinic은 **신월로 280**으로 서로 다르다. 같은 질문에 문서 위치에 따라 다른 주소가 답으로 나올 수 있으므로 AI 인용용 마크업 추가보다 먼저 통일할 문제다. 이번 감사는 불일치 자체를 확인한 것이며 어느 도로명으로 수정할지는 병원의 확인된 원장과 대조해야 한다.

[이비인후과 목록](https://blog.thegungang365.com/category/ent)은 게시글 0개 상태로 200·자기 canonical을 반환하고 noindex가 없다. 목록의 짧은 과목 설명은 있으므로 완전히 무내용인 페이지로 단정하지 않는다. 하지만 글을 기대하고 진입한 환자의 필요를 충분히 해결하는지 검토하고, 필요하다면 관련 진료 안내나 실제 글을 연결한 뒤 색인 대상을 정리하는 것이 좋다. 7개 글에 비해 카테고리·저자·목록 URL이 많은 현재 구성을 페이지 수 증가 성과로 평가하지 않았다.

모바일 성능의 우선 개선점은 의료진·분야 이미지의 크기다. 현재 글쓰기 방식의 강점을 유지하면서 이미지 크기, 색 대비, 작은 터치 영역을 보완하는 편이 효과적인 작업 순서다.

**올림픽파크365 공개 블로그: 넓은 주제 범위와 정보 일치 문제**

사이트맵상 글 형태 URL 78개와 의료진별 프로필·분야 묶음이 있어 세 사이트 중 증상 중심 콘텐츠의 발견 범위가 가장 넓다. 표본 7개 글 모두 citation·author·reviewedBy·lastReviewed가 있고, 직접 답변과 연구의 한계 설명이 나타난다. [의료진 프로필](https://blog.olympicpark365.com/writers/leeyoungki)과 개별 글의 연결도 저자를 추적하기 쉽게 한다. 분량이나 schema 종류가 많다는 이유만으로 의학적 정확성이나 AI 인용 성과를 보증하지는 않는다.

[수면무호흡 검사 글](https://blog.olympicpark365.com/stop-bang-sleep-apnea-screening)의 본문은 평일·주말·공휴일 09:00~22:00로 설명하지만, 동일 페이지의 MedicalClinic은 평일 09:00~23:00, 주말 09:00~22:00이며 푸터도 평일 23시라고 한다. 이는 날짜의 UTC/KST 차이처럼 단순 형식 차이가 아니라 환자의 방문 판단에 영향을 주는 불일치다. 최신 운영 정보로 글과 공통 데이터 모두 맞춰야 한다.

출처의 존재와 주장 정확성도 구분해야 한다. 같은 수면검사 글은 가정수면검사를 확진에 사용할 수 없는 선별 검사로 일괄 설명한다. 반면 AASM의 진단 권고는 적절한 장비와 임상 조건을 충족한 일부 성인에서 가정수면검사를 진단 선택지로 인정한다. 특정 방식의 검사 연구를 가정수면검사 전체로 확대했는지 의료진의 재검토가 필요한 사례다. 이번 지적은 해당 일반화의 범위를 비교한 것으로 전체 글의 의료적 승인·불승인을 판정한 것이 아니다. [AASM 공식 진단 권고 설명](https://aasm.org/aasm-publishes-new-guideline-for-diagnostic-testing-for-adult-sleep-apnea/).

[컨디션·회복 목록](https://blog.olympicpark365.com/series/iv-recovery)은 게시글 0개다. 현재 사용자에게 주는 설명과 연결의 충분성을 검토할 수 있다. 큰 분야 이미지, 홈에서 반복되는 카드 데이터와 모바일 대비·터치 영역도 개선 대상이다. 동일 화면의 반응형·캐러셀 복제 요소를 곧바로 검색 스팸으로 간주하지 않았다.

**2026년 기준에서 잘못 적용하기 쉬운 평가 항목**

Google은 FAQ 리치결과를 **2026년 5월 7일부터 중단**했고 6월에 해당 문서를 삭제했다. 따라서 영통탑에 FAQPage가 없다는 사실을 FAQ 리치결과 기회의 상실로 감점하지 않았다. 환자가 읽는 질문·답변은 여전히 유용하지만 FAQ 스키마 개수와 AEO 품질은 별개다. [Google 공식 변경 기록](https://developers.google.com/search/updates#may-2026).

두 공개 블로그에는 llms.txt와 여러 봇에 대한 Allow 규칙이 있다. 영통탑의 llms.txt는 404였다. 그러나 Google은 llms.txt를 검색 최적화에 사용하지 않으며 그 유무가 Google 노출·순위에 영향을 주지 않는다고 안내한다. 봇 허용은 접근을 허용하는 설정이지 실제 방문·인용 기록이 아니다. 이 Google 안내를 다른 모든 AI 서비스의 동작까지 입증하는 근거로 확대하지 않았다. [Google 생성형 검색 최적화 안내](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide).

FAQ 답변과 본문의 기계적 문자열 비교에서 일부 불일치가 발생했지만, 수동 표본 확인에서는 본문 중간의 차트·캡션 삽입 및 표시 형식 차이가 포함돼 있었다. 이를 모두 내용 불일치로 집계하거나 감점하지 않았다. 반면 주소와 진료시간은 실제 의미가 다른 값이므로 위에서 별도로 지적했다.

**영통탑에 적용할 우선순위**

| 순서 | 구체적 다음 작업 | 완료 기준 |
|---|---|---|
| 1 | 실제 의료·운영 검토 근거를 확보한 뒤 기존 production 검증을 거쳐 검색 공개 전환 | 승인된 대상의 noindex 상태·사이트맵·canonical을 배포 URL에서 재검사. 검토 모드를 임의 해제하지 않음 |
| 2 | 토요일 운영·검사 접수·예약·준비·결과 안내에서 확인 가능한 사실 보강 | 같은 사실이 본문·메타데이터·구조화 데이터·기존 병원 채널에서 일치 |
| 3 | 기존 의료정보에 실제 검토자와 문맥별 출처 연결 보강 | 허위 저자·검토일 없이, 핵심 주장과 근거·검토 책임 주체를 추적 가능 |
| 4 | 현재 검사·증상 페이지의 답변 완결성 개선 | 환자가 무엇을 준비하고 언제 연락해야 하는지 이해. 키워드 변형만을 위한 페이지 추가 없음 |
| 5 | 검색·AI 노출의 실제 측정 시작 | 검색도구의 색인·노출·클릭 자료와 고정 질의의 출처 인용·사실 정확성 기록을 구분 |

현재 속도·모바일 전화와 위치 동선은 유지할 강점이다. 경쟁 사이트의 큰 홈 이미지나 긴 칼럼을 형식만 따라할 필요는 없다. 기존 공지와 사례의 원문 연결도 유지한다. 이번 비교는 공개 페이지·승인 기록·배포 설정을 수정하지 않았다.

실제 측정은 병원명 검색, 지역+검사 검색, 검사 준비 질문, 증상 판단 질문을 나누어 관찰하면 된다. 예를 들어 ‘영통탑내과 진료시간’, ‘망포역 심장초음파 예약’, ‘대장내시경 준비 중 커피’, ‘홀터검사 후에도 두근거림’을 고정 질의로 두되, 자극적인 키워드 변형을 대량 생성하지 않는다. 관찰 날짜·검색 서비스·위치 조건·인용 URL·시간/주소의 정확성을 기록하고, 인용되지 않은 관찰도 남긴다. 서비스별 기능과 검색 결과 변동 때문에 소수 질의의 인용률을 전체 성과로 일반화하지 않는다.

**증거와 재현**

- [collect.mjs](collect.mjs): 공개 URL 읽기와 HTML 메타데이터 수집. 의존성은 저장소 web의 cheerio 사용.
- [http-evidence.json](http-evidence.json): URL별 응답·메타·스키마 종류·사이트맵 목록. 전체 의료 원문은 포함하지 않음.
- [summary.json](summary.json): 페이지 수, 고유 메타, H1, 스키마·citation 통계. URL 수는 색인 수가 아님.
- [findings-evidence.json](findings-evidence.json): 병원 식별자·진료시간·주소와 지적한 불일치의 짧은 발췌.
- [browser-check.mjs](browser-check.mjs), [browser-evidence.json](browser-evidence.json): 모바일 브라우저 홈 관찰과 측정 절차.
- [lighthouse-evidence.json](lighthouse-evidence.json): 같은 장비의 공개 홈페이지별 모바일 1회 진단 결과.

원 HTML·전체 추출 텍스트·화면 캡처·Lighthouse 원본은 git에서 제외되는 `.local/seo-comparison-2026-09-11/`에만 보관한다. 수집 도구의 웹 열기 실패는 실제 HTTP 색인 차단과 구분했고, 실제 값은 Node fetch·Python requests·Edge 관찰로 대조했다. Search Console·Bing Webmaster Tools·Naver Search Advisor·분석 로그에 접근하지 않았으며 실제 순위·색인율·전환율·AI 인용률·외부 평판은 미측정이다.

문서 추가 후 콘텐츠 계약 검사 45개와 기존 로컬 출력의 정적 감사 45개 경로가 통과했다. 문서 JSON·로컬 링크·수집 스크립트 구문도 검사했다. 로컬 검사 결과와 위의 실제 배포 URL 측정은 별도 증거이며, 이 작업에서 사이트를 새로 빌드하거나 배포하지 않았다.
