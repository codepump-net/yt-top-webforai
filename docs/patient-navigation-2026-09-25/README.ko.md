# 환자 목적별 정보구조와 화면 개편

2026-09-25. 내부 구현 기록이며 환자용 정적 사이트에 포함하지 않는다.

## 반영 범위

`plan/원장님요청`을 우선하고 `plan/원장님분석.txt`를 보조 자료로 사용했다. 기존 71개 경로를 유지하고 증상백과(`/symptoms/`), 질환백과(`/diseases/`), 검사 준비(`/preparation/`)의 탐색 페이지 3개를 추가해 총 74개 경로다. 병원 진료에 대한 새 의료 원고를 생성하지 않았다.

- 상단 7개 메뉴: 증상백과, 질환백과, 진료분야, 검사·시술, 암환자 지지진료, 검진·서류, 병원안내.
- 홈: 방문 목적별 4개 진입로, 기존 원고에 근거한 응급 안내, 간결한 증상 링크, 진료와 검사 목록, 암환자 지지진료, 의료진, 방문 정보와 원 공지 채널.
- 상세: 대분류 제목과 논리적 경로, 데스크톱 좌측 고정 목차, 소제목·질문별 이동. 짧은 화면에서는 목차 내부를 스크롤할 수 있으며 모바일은 접이식 목차다. 스크립트가 없을 때도 데스크톱 목차와 모바일의 기본 접이식 목차를 사용할 수 있다. CSS로 화면 크기에 맞는 목차를 처음부터 표시해 로딩 후 접힘으로 인한 화면 이동을 방지한다.
- 하단 반복 관련 카드 제거. 기존 관련 페이지는 좌측의 간결한 관련 안내 또는 일반 링크 목록으로 보존하고, 본문 문맥 링크도 유지했다.
- `/services/`는 검사 안내로, `/conditions/`는 진료분야로 구분했다. 혼합 허브의 임상 설명은 진료분야 쪽에 보존했다.
- `/health/` 주소는 유지하면서 전문 분야와 준비 안내로 연결하는 탐색 페이지로 바꿨다. 개별 원문 주소와 canonical은 유지한다.
- 검진은 건강 확인 / 제출 서류로 구분했다. 내시경·초음파에는 예약·준비·검사 후 확인 과정과 기존 상세 안내 연결을 보강했다.
- 백과는 분야 필터, 가나다순 목록, 제목·본문 검색을 제공한다. 분야 안내와 세부 안내를 표시하고, 검색하면 관련성이 높은 글을 우선한다.
- 모바일 고정 버튼: 전화, 길찾기·시간, 검사 준비. 기존 키보드·작은 화면·인쇄 동작을 유지했다.

## 원고 연결의 한계

원장님 요청에는 증상백과 100편과 질환백과 120편이 확보되었다고 명시되어 있다. 그러나 현재 제공된 저장소와 `plan/`에서 해당 원고 묶음의 위치를 확인하지 못했고 사용자에게 경로를 요청했다. 확보 원고 자체가 없다는 뜻은 아니다.

이번 구현에서는 기존 글 10개를 증상백과, 15개를 질환백과에서 탐색하도록 연결했다. 같은 원문은 복제하지 않고 여러 탐색 경로에서 연결한다. 빈 분야나 미제공 글을 만들지 않았으며 ‘100개 전체 보기’, ‘120편 게시 완료’, 통계 없는 ‘인기 증상’도 표시하지 않았다. 증상 7개 분야 전체 및 질환 120편의 최종 분류는 원고 대조 후 확장할 작업이다.

자료를 받으면 `src/lib/information-architecture.mjs`의 분야 목록에 검토된 글을 연결한다. 신규 글은 `content/pages.json`과 `content/page-intents.json`에 함께 기록하며 기존 글과 중복 여부를 먼저 판단한다. 의료진 소개에 확인되지 않은 경력·진료 철학·검토 이력을 추가하지 않았다.

## AEO·GEO 보존 조건

- 중요한 내용, 전체 백과 링크, 제목·질문·답변은 정적 HTML에 포함된다. 검색창 조작만으로 글을 발견해야 하는 구조가 아니다.
- 화면 목록과 JSON-LD `ItemList`는 같은 분류 원장을 사용한다. 질문·답변, 출처, 기존 canonical·언어별 연결을 유지한다.
- 메뉴와 URL 변경을 분리했다. 기존 주소를 일괄 이동하거나 `yttop.co.kr`을 대체하지 않는다. 원 공지 채널과 사례 원문 25개를 보존한다.
- 새 분류 원장과 목차 렌더러도 공개 승인 digest의 대상에 포함했다. 기존 승인 파일과 의료진 검토 기록을 갱신하지 않았다.
- 출력은 review/noindex다. 이번 구현은 AI 검색 인용 성과나 검색 공개 승인을 의미하지 않는다.

## 검증

실행 결과는 `verification.json`에 기록한다. 검증 범위는 콘텐츠 계약, 정적 출력과 링크·메타데이터·구조화 데이터, 기존 회귀검사, 새 메뉴·백과·좌측 목차·모바일 진입로, 스크립트 없는 탐색과 자동 접근성이다. 일반 루트와 `/yt-top-webforai` 하위 경로에서 각각 확인한다.

위 구현·로컬 검증 단계에는 배포를 포함하지 않았다. 이후 사용자의 커밋·푸시·배포 요청에 따라 74개 경로를 기존 Pages 주소에 배포하고 실제 사이트를 검증했다. [세션 요약·배포 결과](session-summary.ko.md)에 후속 결과를 기록했다.

개편 직후 결과: 루트와 하위 경로 각각 74개 정적 감사 및 브라우저 검사 38개 통과, 단위 검사 59개·lint·타입 검사 통과. 검색·사이트맵 없이도 안내 글에 도달하는 경로를 검증했다. 모바일 Lighthouse 측정은 홈 98, 증상백과 100, 심장초음파 상세 100이며 세 화면 모두 CLS 0이다. 이는 로컬 기술 지표이고 AI 인용 성과가 아니다. 최종 로컬 미리보기는 `http://127.0.0.1:3000/yt-top-webforai/`다.

후속 최종 검토: [요구사항·오타·출처와 신뢰성 검토](final-review.ko.md), [참고 URL 90개와 사례 원문 25개 확인](source-review.json), [수정 후 최종 검증](final-verification.json). 위 개편 직후 지표와 최종 검토 결과를 구분한다.
