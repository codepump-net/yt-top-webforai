# 기존 홈페이지 이미지의 페이지별 사용 계획

기준 자료는 [기존 이미지 원장](../../research/2026-09-11-yttop/data/asset-inventory.csv)의 다운로드 성공 515개다. 사용자의 요청에 따라 병원 정보와 이미지는 기존 홈페이지에서 이관한다. 새 의료진 얼굴·시설·검사 사진을 생성하거나 외부 병원 사진을 가져오지 않는다. UI 아이콘과 구분선 등은 일반적인 코드·CSS로 구현할 수 있다.

## 나머지 자산을 고르는 순서

[페이지별 이미지 후보 CSV](page-asset-candidates.csv)는 **원본 URL과 게시물 ID의 연결 관계로 찾은 후보**다. 로고·푸터처럼 35개 이상 URL에서 반복된 자산은 본문 후보 계산에서 제외했다. 이 휴리스틱은 이미지의 의학적 적합성을 판정하지 못한다. 따라서 연결된 모든 자산을 해당 페이지에 사용하라는 목록이 아니다.

1. 각 페이지의 `source_documents`와 원문 화면에서 실제 본문 영역을 찾는다.
2. 후보 이미지의 원본·OCR·표시 위치를 대조한다. OCR만 읽고 선택하지 않는다.
3. 검사 과정·장비·공간·설명 그림인지 구분하고 의미 있는 것만 선택한다. 해상도만으로 hero를 고르지 않는다.
4. 글자로만 구성된 긴 의료 설명 이미지는 승인된 HTML 원고로 재구성한다. 숫자·단위·예외는 원문과 대조한다.
5. 증례 이미지는 이름·날짜·환자번호·검사번호·병원 화면·드문 조합의 정보가 있는지 개별 검수한다. 판정되지 않은 이미지는 웹 자산으로 복사하지 않는다.
6. 적합한 이미지가 없으면 텍스트·표 중심으로 구성한다. 실제 병원 사진이 없는 영역을 가상의 사진으로 채우지 않는다.

## 배포 자산 생성 규칙

구현 시 `web/scripts/prepare-assets.ts`에서 승인된 `content/assets.json`만 읽는다. Sharp 등의 빌드 도구로 기존 이미지의 리사이즈·포맷 변환을 수행하고 원본 자체는 보존한다. 웹 파생본은 `web/public/assets/{assetId}/{width}.{hash}.webp`처럼 출력한다.

| 분류 | 출력 후보 | 화면 규칙 |
|---|---|---|
| 공간 hero | 폭 640/960/1440/1920 중 원본 이하 | 원본 비율 유지 또는 명시한 크롭; `sizes`·치수 제공; 첫 화면 이미지 우선 로딩 |
| 의료진 | 폭 320/480/800 중 원본 이하 | 얼굴·인물 훼손 없는 위치; 이름·자격을 HTML에 별도 표시 |
| 검사 사진·도해 | 폭 480/800/1200 중 원본 이하 | 상세 읽기 필요성 우선; 아래 영역 지연 로딩 |
| 증례 영상 | 의미 유지 가능한 치수·압축 수준을 의료 검수 | 공개 승인된 비식별 파생본만; 원본 다운로드 자동 제공 안 함 |
| 로고 | 원본 PNG 또는 검증된 기존 벡터 | 투명도·색·비율 보존; 새 로고 디자인 생성 없음 |

원장 필드: `assetId`, `sourceUrl`, `localSource`, `sha256`, `sourcePageIds`, `role`, `width`, `height`, `alt`, `caption`, `crop`, `variants`, `rightsStatus`, `medicalImageReview`, `publish`. 원본에서 새 파일로 이어지는 출처를 끊지 않는다. 이미지가 만료 공지·이전 의료진을 담고 있으면 색상 보정이나 포맷 변경으로 현재 자료가 되지 않는다.

완료 검사: 모든 배포 이미지가 원장에 등록되어 있음, 실제 파일·해시·치수 일치, alt·캡션 확인, 의료 사실 HTML 제공, basePath 경로 200, 원본 161MB 묶음 미배포. 사이트 이미지를 원본 CDN에 직접 의존하는 hotlink 방식은 기본값으로 쓰지 않는다.
