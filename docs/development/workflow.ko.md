# 기능별 개발 절차

기준일: 2026-11-16. 명령은 macOS·Linux의 sh 계열 예시다. Windows는 같은 환경변수를 PowerShell 구문으로 설정한다.

## 1. 개발 환경

저장소 루트에서 먼저 `git status --short`로 기존 변경을 확인한다. 다른 작업의 파일·확인용 HTML·로컬 결과물을 정리 명목으로 삭제하지 않는다.

```sh
node -v
python3 --version
cd web
npm ci
npm run dev
```

Node.js는 24.x(`>=24 <25`)를 사용한다. 최신 전역 Node가 프로젝트 요구 버전과 같다고 가정하지 않는다. Python 실행 이름이 `python3`인 환경에서는 하네스 실행 시 `PYTHON=python3`을 설정한다. `npm ci`는 lockfile의 설치 결과를 사용하고 일반 개발의 시작 단계에서 의존성을 임의 갱신하지 않는다.

개발 서버는 기본 `http://localhost:3000`이다. `.next/`, `out/`, `reports/`는 생성물이므로 기능 구현 파일처럼 직접 편집하지 않는다.

## 2. 기능 하나의 개발 사이클

| 단계 | 작업 | 산출물 |
|---|---|---|
| 발견 | 환자·운영자 문제와 재현 경로 확인 | 기능 ID와 문제 문장 |
| 정의 | 현재/변경 동작·범위·상태·의존성·완료 조건 작성 | 기능 명세·작업 카드 |
| 영향 분석 | 원장·공통 컴포넌트·검색·SEO·출판 영향 확인 | 변경 파일과 검사 목록 |
| 구현 | 작은 단위로 데이터·화면·필요 로직 수정 | 코드·원고 차이 |
| 검증 | 관련 계약·정적 출력·실제 동작 확인 | 결과·오류·제약 기록 |
| 인수 | 명세·경로표·백로그·필요한 운영 문서 갱신 | 검토 가능한 PR |
| 배포 | 현재 공개 근거·CI·실제 사이트 대조 | 해당 실행의 SHA·증거 |

새 기능은 [템플릿](../templates/feature-spec.ko.md), 작은 개선은 [작업 카드](../templates/task.ko.md)를 사용한다. 의미 있는 구조·정책 선택만 [ADR](../decisions/README.md)로 남긴다.

## 3. 작업 분해 예시: F09 검색 용어 개선

하나의 개선에서 ‘검색 전체 고도화’를 목표로 삼기보다, **기존 안내에 연결할 환자 용어 1개와 예상 결과**를 명시한다. 우선 현재 결과를 확인하고 이미 작동하면 실패를 꾸미지 않고 현행 동작의 문서화·회귀 검토로 범위를 조정한다.

1. 대상 안내 ID·검색어·예상 결과·제외 대상을 기록한다.
2. 원고의 실제 내용에 맞는 별칭인지 확인한다.
3. `search-aliases.json`과 필요한 작은 로직만 수정한다.
4. 결과·분야 필터·검색어 비전송·색인 실패 상태를 확인한다.
5. 원고·분류·렌더러의 공개 근거 영향과 필요한 검사를 기록한다.

실습의 구체적인 제출물은 [Lecture 09 워크숍](../lectures/pwd-2026-2/lecture-09/workshop.ko.md)을 참고한다.

## 4. 변경 종류별 원칙

| 변경 | 원칙 |
|---|---|
| 원고·새 경로 | 목적 원장·근거·날짜·관련 안내·분류·실제 확인 |
| 공통 UI | 기존 모바일·키보드·목차·인쇄 수정 보존 |
| 분류·검색 | 허브·사이트맵·검색·JSON-LD의 같은 관계 |
| 구조 분리 | 먼저 출력 동등성 확인, 새 파일의 digest 포함 검토 |
| 의존성 | Node·lockfile·취약점·빌드·브라우저 호환을 함께 확인 |
| 측정 | 방문자 UI·입력 수집 없이 가능한 범위로 제한 |
| 문서 | 현행 명세와 날짜별 증거를 구분하고 출처 링크 유지 |

초기 수입기·정리 스크립트의 재실행은 평상시 원고 수정 방법이 아니다. 현재 편집 내용을 덮어쓸 수 있으므로 입력·변경 범위를 읽고 필요한 경우에만 사용한다.

## 5. PR에 담을 내용

PR은 문제와 결과 동작으로 시작하고 기능 ID, 범위, 실제 확인 방법·결과, 의료·운영 확인이 필요한 내용, 배포 여부를 적는다. 스크린샷·로그는 실제 파일로 연결하고 실행하지 않은 검사를 통과했다고 쓰지 않는다.

현재 CI는 docs 인벤토리 도구를 자동 실행하지 않는다. 문서·경로 변경 작업자는 저장소 루트에서 `node docs/tools/update-inventory.mjs --check`를 수행한다. CI 편입은 [B01](../roadmap/backlog.ko.md)의 후속 제안이다.
