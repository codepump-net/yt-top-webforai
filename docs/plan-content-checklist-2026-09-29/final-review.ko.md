# 최초 요청·체크리스트·개발 결과 최종 재검토 — 재제작 전 기록

> **과거 시점 기록:** 아래 수량·미완료 판정은 당시 상태를 보존한 것이다. 현재 콘텐츠 판정은 공식 16쪽 적용 후 54개 충족·부분 충족 0개·미충족 0개다. 이식 패키지는 논이슈이며 집계에 포함하지 않는다. [최신 결과](infection-resolution.ko.md) · [작업 범위 확인](scope-clarification.ko.md).

검토일: 2026-09-29. 대상은 이식 절차를 제외한 `plan/` 문서 7개, 54개 검수 기준, 현재 소스와 로컬 정적 출력이다. **전체 요청은 아직 미완료다. 원본 콘텐츠 반영과 추가 코드 보완이 남아 있다.**

## 1. 주요 발견 사항

### R1. 감염병 원문 15쪽이 게시되지 않았다 — 필수 미완료

- 실제 감염병 상세 화면의 원문 이미지 **0/15개**, 요청 원본 PDF 링크 **0개**다.
- 공지에 `document`가 등록되지 않아 [원문 표시 부분](../../web/src/components/notice-document.tsx)이 렌더링되지 않는다. 지정 제목, 기존 통계 요약과 외부 통계 PDF 링크만 있다.
- 기존 통계 PDF는 `pdfinfo`로 **38쪽**을 다시 확인했다. 요청한 15쪽 원문으로 판정할 수 없으며, 미확보 원고와의 내용 동일성도 검증하지 못했다.
- **완료 조건:** 실제 요청 PDF 확보 → 전체 15쪽 이미지 생성·순서대로 등록 → 원문과 문구·수치·잘림 전수 대조 → 동일 PDF와 각 이미지 원본 보기 확인.
- 관련 기준: INF-02~06, BOARD-11, VERIFY-02~03.

### R2. 최초 PNG 17개 교체와 배너 내부 용어 교정이 남았다 — 필수 미완료

- [이미지 원장](../../content/assets.json)의 대상 17개는 모두 기존 WebP다. `/assets/clinic-visuals-hq/*-hq-original.png`에 해당하는 자산은 **0/17개**다.
- 현재 암환자 배너를 직접 열면 **‘암 치료 중 지지진료’**가 남아 있다. HTML·메타·ALT의 20곳 치환만으로 그림 안 문구의 교정까지 완료되지는 않는다.
- 신장 배너는 콩팥 그림 위에 **‘심장질환’**이라고 표시된다. 기존 추가 확인 사항이며 최초 요청의 필수 항목 개수에는 더하지 않았다.
- **완료 조건:** 17개 최초 PNG의 대응 확인 → 지정 경로·파일명 등록 → 암환자 그림 문구 교정 확인 → 17개 표시·비율·픽셀 폭·원본 보기·캐시 갱신 전수 확인. 신장 원본의 제목도 확인한다.
- 관련 기준: TERM-04, IMG-01~03, IMG-05, VERIFY-02~03.

### R3. 로컬 미리보기에서 PNG·PDF가 다운로드된다 — 코드 보완 필요

- [미리보기 서버](../../web/scripts/serve.mjs)의 MIME 목록(13~23행)에 `.png`와 `.pdf`가 없다. 두 형식 모두 `application/octet-stream`으로 응답한다.
- 임시 폴더에 기존 PNG·PDF를 넣어 **HTTP 200이지만 링크 클릭 시 둘 다 다운로드 이벤트가 발생함**을 재현했다. [재현 결과](review-evidence/preview-mime.json).
- 이는 로컬 검증 서버에서 확인한 문제다. GitHub Pages의 응답 형식까지 같은 것으로 추정하지 않았다.
- **보완:** `image/png`, `application/pdf` 매핑을 추가하고 PNG·PDF 새 창 열기의 실제 동작을 검사한다. 원본 파일을 받은 뒤 자료별 원본 보기 확인에도 포함한다.
- 관련 기준: INF-04~05, IMG-05, VERIFY-02.

### R4. PNG 원본 반영 시 기존 이미지 검증 규칙을 보완해야 한다 — 코드 보완 필요

- [파일 검사](../../web/scripts/validate.mjs) 23행은 모든 이미지에 **200,000바이트 상한**을 적용한다. 이 크기를 넘는 최초 PNG는 그대로 등록하면 거절된다. 실제 원본 용량은 아직 알 수 없다.
- [안내도 검사](../../web/scripts/patient-additions-contract.mjs) 109~114행은 `sourceCrop`이 없을 때 `sourceSha256`을 안내문 JSON 해시와 비교한다. 원본 파일 SHA와 안내문 SHA를 각각 보존하며 잘라내기 정보를 제거한 조건에서 `Diagram guidance is stale: heart-flow` 오류를 재현했다. [메타데이터 조건 재현](review-evidence/review.json).
- 재현에 쓴 과거 생성 PNG는 검사 분기 확인용이며 요청된 원본으로 사용하지 않았다.
- **보완:** 원본 파일 무결성 해시와 안내문 해시의 역할을 분리하고, 최초 PNG에 적용할 용량 기준을 정한다. 검증 전체를 제거하거나 압축 WebP로 바꾸어 완료 처리하지 않는다.
- 관련 기준: IMG-01~02, VERIFY-01.

### R5. 일반 검사 통과가 필수 이미지의 존재를 보장하지 않는다 — 최종 검수 보완 필요

- 현재 콘텐츠 검사는 감염병 `document`가 선택 항목이고, 지정 PNG 17개의 존재·경로는 필수 조건으로 검사하지 않는다.
- 실제 원본 이미지 0개·원본 PNG 0개인 현재 상태에서 콘텐츠 검사가 오류 없이 통과함을 재확인했다.
- 기존 브라우저 검사의 이미지 확인도 현재 자산 원장을 기준으로 하므로 기존 WebP의 정상 표시를 검사한다. 이전에 보고한 테스트 통과 횟수 자체는 실제 기록과 일치한다.
- **보완:** 최종 요청 완료 검사에 `원본 PNG 17개`, `지정 경로`, `감염병 15개 이미지와 동일 PDF`, `배너 그림 안 용어`를 필수 증거로 추가한다. 파일 개수·경로는 자동 검사하고 원문 동일성과 그림 글자는 시각 검수 증거를 남긴다.
- 관련 기준: VERIFY-01~04 및 해당 콘텐츠 기준.

## 3. 체크리스트 판정 검토

### 원문 최종 체크리스트

원문 42개 중 이식 패키지 전용 검사 2개를 제외한 **40개**를 대조했다. 원문 항목에 대응하는 필수 기준 중 구현되지 않은 것이 있으면 미충족으로 판정했다.

| 판정 | 항목 수 |
|---|---:|
| 충족 | 27 |
| 부분 충족 | 4 |
| 미충족 | 9 |
| 이식 절차로 제외 | 2 |

원문 행별 요구·검수 ID·판정은 [40개 전수 대조](review-evidence/original-checklist.json)에 기록했다. 병원안내의 공식 채널 등 다른 plan 문서에만 명시된 요구도 54개 확장 체크리스트에 포함되어 있다. 최초 문서 7개의 해시는 조사 당시와 모두 같다.

### 54개 확장 체크리스트

**충족 41개 · 부분 충족 5개 · 미충족 8개**로 정리한다. 기존의 ‘확인 필요 8개’는 구현 여부를 모르는 항목이 아니라, 요청한 자료가 실제로 반영되지 않은 항목이다. 미충족 사유로 원본 자료 대기를 함께 기록했다.

- 부분 충족: BOARD-11, IMG-03, IMG-05, VERIFY-02, VERIFY-03.
- 미충족: TERM-04, INF-02~06, IMG-01~02.
- [재검토 판정 원장](review-evidence/requirement-results.json). 기존 `evidence/`의 검사 기록은 개발 당시의 기록으로 보존했다.

이 항목 수를 개발 완료율로 환산하지 않는다. PDF 15쪽과 PNG 17개 같은 주요 작업과 작은 확인 항목의 비중이 같지 않다.

## 4. 이번에 재확인한 정상 동작

- 현재 콘텐츠 해시가 마지막 프로젝트 경로 빌드와 일치하고, **135개 출력 HTML의 해시도 모두 일치**한다. 기존 테스트가 다른 원고를 대상으로 수행된 상태는 아니다.
- 콘텐츠 구조 검사 오류 0개. 공개 HTML에서 이전 용어 0건. 비트맵의 잔존 글자는 R2에 별도로 기록했다.
- 전체 135개 경로의 푸터에서 세 공식 채널 링크를 확인했다.
- 배너 12개 × 모바일·데스크톱 **24조건**에서 자연 픽셀 폭 이내 표시를 확인했다.
- 확대창 5개 × 모바일·데스크톱 **10조건**에서 자연 픽셀 폭 이내 표시, Escape 닫기, 원래 링크로 포커스 복귀를 확인했다.
- 공지 세 분류가 각각 3편·2편·1편을 표시한다. 인플루엔자 표는 모바일에서 6행을 유지하고 표 영역의 가로 스크롤이 동작한다.
- 인플루엔자 표의 6개 대상별 시작·종료일은 [질병관리청 예방접종도우미](https://nip.kdca.go.kr/irhp/infm/goVcntInfo.do?menuCd=134&menuLv=1)와 다시 대조해 일치했다. 출처 확인은 2026-09-29에 수행했다.
- 이번 대상 화면 확인에서 브라우저 실행 오류는 없었다. [브라우저 확인](review-evidence/browser.json) · [원고·출력·검사 재확인](review-evidence/review.json).

기존 기록의 단위 검사 78개·전체 브라우저 검사 62개·프로젝트 경로 14개·모의 성능 7개 통과는 [당시 검증 기록](evidence/verification.json)으로 확인했다. 이번 검토에서는 변경 없는 전체 빌드·검사·성능 측정을 반복하지 않고 해시 대조와 발견 사항 재현, 필요한 화면 확인을 수행했다. 운영 배포 결과를 검사한 것은 아니다.

## 5. 후속 작업 순서

1. 로컬 PNG·PDF 응답 형식과 원본 PNG 검증 규칙을 보완한다.
2. 원본 PNG 17개와 요청한 15쪽 PDF를 확보해 자산별 대응과 문서 동일성을 확인한다.
3. 배너 내부 용어, 지정 PNG 경로, 15쪽 순차 이미지와 같은 PDF를 반영한다.
4. 필수 콘텐츠 존재 검사와 시각 검수 증거를 추가하고 13개 미완료 기준을 재검수한다.
5. 실제 변경분의 콘텐츠·출력·브라우저·성능 검사를 실행한 뒤 완료 판정을 갱신한다. 운영 배포·의료 및 운영 승인 여부는 별도 실제 기록으로 확인한다.

이번 검토 결과는 ‘원본 파일을 받으면 단순 복사만 하면 되는 상태’보다 남은 범위가 넓다. 위 코드 보완과 최종 검수까지 포함해야 최초 요청을 완료할 수 있다.
