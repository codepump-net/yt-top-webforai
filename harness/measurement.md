# 질문·외부 정보·배포 후 측정

## 질문 세트

다음을 검증된 실제 지역·진료 범위로 바꾸고 ID를 고정한다. 병원명 포함 질문과 비포함 질문은 별도 분석한다. 존재하지 않는 서비스나 환자 개인정보를 입력하지 않는다.

| ID | 질문 예시 |
|---|---|
| visit-hours | [병원명]의 평일·주말 진료시간과 접수 마감은? |
| visit-holiday | [병원명]은 [날짜] 공휴일에도 진료하나요? |
| visit-parking | [병원명] 주차 위치와 지원 조건은? |
| visit-location | [병원명]의 도로명 주소와 대중교통 경로는? |
| doctor-profile | [의료진명]의 전문 분야와 확인 가능한 경력은? |
| service-scope | [지역]에서 [증상]을 진료하는 기관과 진료 범위는? |
| service-test | [병원명]에서 [검사]를 받으려면 준비가 필요한가요? |
| service-cost | [병원명]의 [공개된 비급여 항목] 비용은 어디서 확인하나요? |
| symptom-explain | [증상]의 흔한 원인과 진료가 필요한 경우는? |
| symptom-urgent | [의료진이 정한 응급 증상]이 생겼을 때 먼저 무엇을 해야 하나요? |
| treatment-evidence | [치료] 효과의 근거가 적용되는 대상과 한계는? |
| alternatives | [진료 영역] 치료 선택지를 비교할 때 무엇을 확인하나요? |

질문마다 의도·브랜드 여부·기대 사실·잘못된 답·근거 URL·담당자를 기록한다. `measure`가 읽는 `queries`에는 유일한 `id`가 필요하며 추가 필드는 연구 메타데이터로 사용할 수 있다.

## 절차와 지표

1. 변경 전 같은 엔진·언어·지역·로그인 조건에서 질문을 반복 실행한다. 2~4주는 초기 관측 기간 제안이며 공식 최적 기간이 아니다.
2. 실제 답변 전문, 표시된 출처 URL, 실행 시각, 엔진/모델 표시명, 성공·실패를 저장한다. 모델에게 학습 출처를 묻는 것은 실제 인용 로그의 대체물이 아니다.
3. 사실·저자·근거 조건을 먼저 개선하고 변경 날짜·URL·수정 종류를 남긴다. 동시에 여러 요소를 바꾸면 효과를 분리하기 어렵다.
4. 크롤링·색인 확인 후 같은 조건으로 재관측한다. 가능하면 변경하지 않은 유사 주제도 관찰한다. 표본 수와 변동성을 함께 보고하며 관측 차이를 바로 인과 효과로 부르지 않는다.
5. 문의·예약은 별도 분석 도구로 측정한다. 인용·클릭·유효 문의는 서로 다른 성과다. 리퍼러가 없는 방문을 모두 AI 유입으로 추정하지 않는다.

관측 JSON은 [합성 예제](examples/observations.json)를 따른다. 자동 질문 실행·외부 계정 연결은 구현하지 않았다. 합성 답변을 실제 성과에 혼합하지 않는다.

| 지표 | CLI 정의 |
|---|---|
| citation_rate | 유효 답변 중 대상 도메인이 출처인 비율. 호스트명 완전 일치, 하위 도메인은 별개 |
| mention_rate | 유효 답변 중 병원명 별칭이 문자열로 나타난 비율. 추천·긍정을 뜻하지 않음 |
| query_coverage | 질문 세트 중 유효 답변을 확보한 질문 비율 |
| errors | 실패 수. 비인용 답변으로 계산하지 않음 |
| accuracy_rate_labeled_only | 검토자와 true/false 판정이 있는 답변의 정확 비율. 판정 표본 수도 보고 |

엔진·언어·기간별로 묶고 같은 질문·run_id 중복은 거부한다. 신뢰구간·인과 추정은 미구현이다. 브랜드별 보고는 입력을 나누거나 집계기를 확장한다. 검색 콘솔과 Bing 인용 보고는 측정 범위가 달라 합산하지 않는다. [Bing AI Performance 공식 안내](https://blogs.bing.com/webmaster/February-2026/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview)

## 외부 사실과 최신성

| 대상 | 대조 내용 | 기록 |
|---|---|---|
| 자체 사이트 | 이름·주소·전화·시간·휴진·의료진 | 기준 버전·확인일 |
| Google 비즈니스 프로필 | 공개 운영정보·사이트 링크 | URL·담당자·대조일 |
| 네이버 플레이스·카카오맵 | 공개 운영정보·예약/위치 링크 | 불일치·수정 상황 |
| 공식 기관·의료진 자료 | 자격·기관 지위·경력 | 증빙·유효 시점 |
| 언론·학회·공공 정보 | 병원명 언급의 맥락·사실 | 오류 정정 여부 |

플랫폼의 실제 필드와 수정 가능 여부는 해당 서비스에서 확인한다. 인위적인 추천·가짜 리뷰·대량의 지역명 교체 페이지를 제작 전략으로 사용하지 않는다. 고유한 운영 조건과 의료진이 설명할 수 있는 근거를 축적한다.

수정·삭제 시 실제 페이지·내부 링크·sitemap·외부 정보를 함께 갱신한다. 참여 검색엔진에는 IndexNow 알림을 선택적으로 연결할 수 있지만 하네스는 외부 제출을 하지 않는다. 알림은 색인·인용을 보장하지 않는다. [IndexNow 공식 FAQ](https://www.indexnow.org/faq)

## 릴리스 운영

로컬 검사 후 배포 환경의 HTTP·robots·헤더·canonical·sitemap·렌더링을 재확인한다. 모바일 실측과 문의/예약 완료 흐름을 확인한다. 임상 내용과 운영 사실은 책임자가 승인한 버전으로 배포한다. 이후 정보 변경·깨진 출처·잘못된 AI 답변을 추적해 원인 페이지를 고친다. 업데이트 주기는 진료시간·의료진 변경·새 근거 등 실제 변경 사건을 우선한다.
