# 병원 사이트 제작 실행 지침

## 목적과 입력

목적은 병원 정보를 정확히 전달하고 검색·답변 시스템이 해석할 수 있는 사이트를 일관되게 제작하는 것이다. 특정 AI 인용률이나 순위를 보장하지 않는다.

필수 입력: 실제 병원명·운영 도메인·주소·전화·진료/휴게/접수/공휴일 정책, 의료진 원본 경력·자격, 실제 진료/검사 제공 범위, 콘텐츠 원문과 근거, 검수 책임자, 디자인 자산, CMS·예약 연결 방식. 없는 사실은 추정하거나 기존 두 병원의 값을 복사하지 않는다. 미확인 상태로 관리하며 예제는 미리보기에서만 사용한다.

## 제작 단계

| 단계 | 작업 | 산출물 | 통과 기준 |
|---|---|---|---|
| 1. 사실 확정 | 병원·의료진·시간·서비스 수집 | 병원별 project.json·정보 확인 기록 | 실제 운영 담당자 대조 |
| 2. 질문 설계 | 환자 여정·위험도·대표 질문 분류 | 질문 ID와 담당 페이지 | 유사 질문은 통합, 응급 의도 별도 |
| 3. 구조 설계 | 페이지·내부 링크·개체 ID 설계 | 사이트맵·페이지 명세 | 원본 HTML과 안정적 URL 가능 |
| 4. 원고 작성 | 질문 답변·조건·근거·한계 | articles·sources | 출처의 대상·시점·지표 대조 |
| 5. 제작 | 데이터 참조 렌더링·디자인·모바일 | 정적 프리뷰 또는 CMS 구현 | 임의 정보 복제 없음 |
| 6. 검증 | 자동 검사·원문 대조·브라우저 확인 | 검사 JSON·의료 검수·화면 | 중요한 사실·응급 안내 오류 없음 |
| 7. 릴리스 후보 | 현재 내용 해시 검수 확인 | release build·릴리스 기록 | 자동 통과와 수동 게이트 모두 충족 |
| 8. 운영 측정 | 실제 로봇·색인·질문·전환 추적 | 관측 데이터·변경 이력 | 분모·미측정 항목 명시 |

## 최종 페이지 구성

- 홈: 병원 정체성, 확인된 진료 시간, 핵심 진료 분야, 의료진, 방문 경로. 최신 글 전체를 한 번에 실어 이미지 자원을 늘리지 않는다.
- 진료 분야: 제공 범위, 대상, 검사 가능 조건, 제한, 담당자, 다른 기관이 필요한 경우. 내용이 실질적으로 다를 때 고유 URL을 만든다.
- 의료진: 고유 인물 ID, 이름·전문분야·실제 경력·자격·소속을 구분하고 담당 글과 연결한다.
- 건강 글: 질문, 대상·조건을 담은 답변, 위험 신호, 설명, 근거, 한계, 검토자·검토일, 적합한 다음 행동.
- 방문 안내: 공식 주소·지도·교통·주차·진료/휴게/접수/예외 시간. 모든 페이지의 안내와 같은 원장 사용.
- 비용·서류·예약: 병원이 확인한 범위·기준일·예외·문의 경로. 실제 적용 내용에 대한 병원 검수 필요.
- 개인정보·이용 안내: 실제 수집 항목과 예약 방식에 맞는 운영 문서. 예제 문서를 그대로 공개하지 않는다.

기본 생성기는 홈·방문·의료진·건강 글의 참조 구조를 시연한다. 진료 분야 전용 템플릿, 날짜별 공휴일 예외, 비용/서류 페이지, 지도·예약·개인정보 동작은 대상 병원 프로젝트에서 완성한다. [coverage.md](coverage.md)에 자동화 범위를 명시했다.

## 콘텐츠 제작 규칙

1. 의료진 자기소개를 글별 자유 텍스트로 재작성하지 않고 인물 객체를 참조한다. 글 전체의 임상 경험 서술도 본인이 확인해야 한다.
2. 주소·시간·전화·주차는 사실 토큰으로 참조한다. JSON-LD 역시 같은 원장으로 생성한다.
3. 논문의 제목이나 링크만 붙이고 주장 검증을 생략하지 않는다. 실제 문장과 원문의 여섯 조건을 대조한다.
4. 숫자·도표에는 모집단·분모·누적/추가·시점·측정 지표를 표시한다. OR을 위험비나 확률 차이로 바꾸지 않는다.
5. 응급 페이지는 의료진이 확정한 긴급 행동을 먼저 제시한다. 예약·비용 안내 때문에 행동이 지연되는 문맥을 피한다.
6. 읽기 좋은 질문·표·목록을 사용하되 고정 단어 수·모든 문단 지역명 삽입·schema 수 늘리기를 목표로 삼지 않는다.
7. 이미지의 캡션과 alt를 분리하고 의료 사실을 이미지에만 넣지 않는다. 도표의 핵심 자료는 텍스트로도 제공한다.
8. 검토 날짜를 게시일로 자동 대체하지 않는다. 의학적 내용·병원 사실·근거가 바뀌면 검수를 갱신한다.

## 작업 지시 템플릿

다른 개발자나 제작 에이전트에 다음을 전달한다. 자동 에이전트 위임을 요구하지 않는 역할별 작업 명세다.

**데이터 작업:** 승인된 병원 원장을 입력받아 project 계약에 맞춰 변환한다. 사실마다 원본 자료·확인 담당자·확인일을 작업 기록에 남긴다. 누락은 입력 대기로 표시한다.

**콘텐츠 작업:** 질문 ID, 위험도, author_id와 근거 목록을 입력받아 문서를 작성한다. 치료 효능·경력·시설·통계를 추측하지 않는다. scope 불일치는 숨기지 않고 검수 항목으로 보고한다.

**프론트엔드 작업:** 승인된 데이터와 디자인에서 원본 본문·보이는 대표 제목·연결 가능한 URL·공통 JSON-LD를 생성한다. 사실을 컴포넌트에 하드코딩하지 않는다. 예약 시스템을 붙일 때 실제 완료까지 검증하되 테스트 데이터와 운영 데이터를 구분한다.

**검수 작업:** 자동 결과, 실제 화면, 의료 원문을 함께 본다. 문장 자체의 의학적 타당성·저자 경력 귀속·응급 행동·단독 인용 시 오해 가능성을 확인한다. 검수자가 아닌 제작 도구가 approved를 대신 기록하지 않는다.

## 릴리스 완료 조건

자동 코드 통과에 더해 실제 병원 데이터 확인, 의료진 원문 검수, 배포 헤더·robots·canonical·sitemap, 실제 폰 화면과 접근성, 성능·예약·전화·지도, 비용·개인정보 문서, 외부 지도 정보가 확인돼야 한다. 검수 승인에 대한 판단과 기록은 병원 프로젝트의 기존 권한 체계로 처리한다. 이 하네스는 별도의 대화상 승인 절차를 강제하지 않는다.

배포·외부 계정 수정은 해당 프로젝트에서 이미 부여된 권한과 범위에 따른다. 공개 후에는 오류 정정·정보 갱신과 관측 지표를 다음 제작 주기에 반영한다.
